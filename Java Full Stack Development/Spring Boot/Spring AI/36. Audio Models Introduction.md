# Introduction to Audio Models: Speech-to-Text and Text-to-Speech

## Moving to Audio

We've now covered text (chat, embeddings, RAG) and images (generation and analysis). The next area to explore is **audio**. Just like with images, audio works in **two directions**:

1. **Speech-to-Text (Transcription)** → Give the AI an audio recording, and get back written text
2. **Text-to-Speech** → Give the AI written text, and get back spoken audio

## Where to Find This in Spring AI's Documentation

If you check the official **Spring AI documentation**, under **Models → Audio Models**, you'll find exactly these two categories:

- **Transcription** (Speech-to-Text)
- **Text-to-Speech**

## Understanding Transcription (Speech-to-Text)

### What Is It?

Transcription takes a piece of **speech (audio)** and converts it into **written text**.

### A Practical, Real-World Use Case: Subtitles

A very common use of this technology is generating **subtitles/captions** for videos.

> If you've ever watched a video on **YouTube**, **Udemy**, or similar platforms and noticed automatically generated captions — that's very likely powered by this exact type of technology. The platform (or the content creator) uses a transcription model to convert the spoken audio into text, which then becomes the subtitles you see on screen.

### How Transcription Works (Conceptually)

```
Audio (speech)
      |
      v
Audio Transcription Model (uses AI/algorithms behind the scenes)
      |
      v
Text (written transcript)
```

You don't need to worry about the internal algorithm — you simply provide the audio, and the model handles converting it into text for you.

## Choosing a Provider for Transcription

According to Spring AI's documentation, there are currently **two providers** that support transcription:

- **Azure OpenAI**
- **OpenAI**

Since this course has focused on **OpenAI** throughout, we'll continue using **OpenAI's transcription model**.

### Why This Is Convenient for Us

Since we already added the **OpenAI dependency** much earlier in this course, we **don't need to add any new library or dependency** just for transcription — it's already included as part of what we set up before. We can jump straight into using it.

> The specific class we'll use is Spring AI's **OpenAI Audio Transcription Model**, which handles the "give speech, get text" flow we described above.

> We'll also explore some additional configuration **options** for transcription (similar to how we explored Image Options earlier) in upcoming topics.

## Understanding Text-to-Speech

### What Is It?

Text-to-speech works in the **opposite direction**: you provide written **text**, and the AI generates spoken **audio** based on it.

```
Text (written words)
      |
      v
Text-to-Speech Model
      |
      v
Audio (spoken speech)
```

### Choosing a Provider for Text-to-Speech

For text-to-speech, Spring AI's documentation currently lists only **one provider**: **OpenAI**.

Just like with transcription, since we already have the OpenAI dependency set up, we can go ahead and use OpenAI's **Audio Speech Model** without any additional setup.

### What Can You Customize?

According to the documentation, text-to-speech generation supports a few customizable options, including:

- **Voice** → different voice styles/tones the generated speech can use
- **Speed** → how fast or slow the generated speech sounds

> We'll explore these customization options in more detail in upcoming topics, similar to how we explored Image Options (quality, style, size) earlier in the course.
