# Sending Your First Request to OpenAI Using Spring AI

## Goal

Now that our project is set up and the API key is added, it's time to actually **test it**. We want to:

1. Send a question (prompt) to our Spring Boot application
2. Let it talk to OpenAI
3. Get a real AI-generated response back

We are **not** building a full chat application here (like a chat window with back-and-forth conversation). We are keeping it simple:

> Send one question → Get one response.

## Tools Needed

To send requests to our application, we need an **API client**. Some common options:

- **Insomnia**
- **Postman**
- Or even a normal **web browser** (works for simple GET requests)

In this tutorial, **Insomnia** is used.

## Step 1: Try Sending a Request (Before Adding Any Code)

Our application runs on:

```
http://localhost:8080
```

Let's try sending a request with a question in the URL:

```
http://localhost:8080/what is Java
```

**Result:** `404 Not Found`

This happens because there is **no controller** in our backend to handle this request yet.

Let's try a slightly different URL:

```
http://localhost:8080/api/what is Java
```

**Result:** Still `404 Not Found` — again, because there is still no controller handling `/api`.

> **Lesson:** Just running the Spring Boot server is not enough. We must write a **controller** to accept and handle incoming requests.

## Step 2: Create a Basic Controller (Without AI First)

Let's first build a simple controller and confirm that basic request handling works — **before** adding any AI code. This helps us catch mistakes early.

### Create the Controller Class

1. Right-click on your package → **New → Class**
2. Name it clearly based on the provider you're using, for example: `OpenAIController`
   - (If you add Anthropic or Ollama later, you would create separate controllers like `AnthropicAIController` or `OllamaAIController`)

### Mark It as a REST Controller

We use the `@RestController` annotation so Spring knows this class will handle web requests and return data directly (not a webpage).

### Add a Method to Handle the Request

```java
@RestController
public class OpenAIController {

    @GetMapping("/api")
    public String getAnswer() {
        return "Hello World";
    }
}
```

**Explanation:**

- `@GetMapping("/api")` → tells Spring: "When someone sends a GET request to `/api`, run this method"
- `getAnswer()` → our method name (you can name it anything meaningful)
- For now, it simply returns the text `"Hello World"`, just to check if things are working

### Test It

1. Restart the server
2. Send the request again to `/api`
3. Nothing happens / still not working correctly at first, because we also need to **accept the message** sent in the URL

### Accepting the Message Using `@PathVariable`

We update the code to accept the message from the URL and print it (just to confirm it's working):

```java
@RestController
public class OpenAIController {

    @GetMapping("/api/{message}")
    public String getAnswer(@PathVariable String message) {
        System.out.println(message);
        return "Hello World " + message;
    }
}
```

**Explanation:**

- `{message}` in the path tells Spring: "This part of the URL is a variable"
- `@PathVariable String message` → captures that value from the URL and stores it in the `message` variable

### Test Again

Send a request like:

```
http://localhost:8080/api/what is Java?
```

**Result:**

```
Hello World what is Java?
```

This confirms that our controller is correctly **receiving and handling** the request. At this point, there is still **no AI involved** — we are just testing basic request handling.

## Step 3: Connect to OpenAI Using ChatModel

Now that basic request handling works, let's actually connect to OpenAI.

### Understanding Chat Models

Spring AI provides different "layers" to help you talk to an LLM. One of these layers is called the **Chat Model**.

```
Your Spring Application
        |
        |  (uses)
        v
    Spring AI
        |
        |  (provides abstraction through)
        v
    Chat Model  --------->  LLM (example: OpenAI)
```

- Each LLM provider has its **own Chat Model** implementation
- Since we are using **OpenAI**, we will use the **OpenAI Chat Model**
- This class comes from the package: `org.springframework.ai.openai`
- We are able to use this because we added the OpenAI dependency in our `pom.xml` file earlier

### Injecting the ChatModel

Instead of manually creating the `ChatModel` object ourselves, we let **Spring handle it** using **Dependency Injection**. We do this through the controller's constructor:

```java
@RestController
public class OpenAIController {

    private final ChatModel chatModel;

    public OpenAIController(ChatModel chatModel) {
        this.chatModel = chatModel;
    }
}
```

**Explanation:**

- `ChatModel chatModel` → a reference to the chat model object
- Spring automatically creates this object and passes ("injects") it into our controller when the application starts
- This is called **Constructor Injection**

### Using ChatModel to Send the Message

Now let's update our method to actually send the message to OpenAI and return the real response:

```java
@RestController
public class OpenAIController {

    private final ChatModel chatModel;

    public OpenAIController(ChatModel chatModel) {
        this.chatModel = chatModel;
    }

    @GetMapping("/api/{message}")
    public String getAnswer(@PathVariable String message) {
        String response = chatModel.call(message);
        return response;
    }
}
```

**Explanation:**

- `chatModel.call(message)` → sends the `message` (our prompt) to OpenAI and waits for a response
- The `call()` method has multiple versions — it can accept a plain `String`, or a more advanced `Prompt` object (covered later)
- For now, we are keeping it simple by just passing a `String`
- The result is stored in the `response` variable and returned back to the caller

> That's it — with roughly **10 lines of code**, we have connected our Spring Boot application to OpenAI.

## Step 4: Test the Real AI Response

1. Restart the server (no errors shown)
2. Send a request again:

```
http://localhost:8080/api/what is Java
```

**Result:** It takes a little time to respond (because it is contacting the OpenAI server over the internet), but eventually you get a real, AI-generated answer explaining what Java is.

This confirms that our application is successfully:

1. Receiving a message from the user
2. Sending it to OpenAI using `ChatModel`
3. Returning OpenAI's real response back to the user

## What's Next: Limitations of This Simple Approach

Using `chatModel.call(message)` with a plain `String` is great for **simple use cases**, but it has limitations. Sometimes you need more control, such as:

- Sending a **system message** (instructions about how the AI should behave)
- Building a proper **structured prompt**
- Working with **metadata**

For these advanced needs, Spring AI provides another option called **ChatClient**, which we will explore separately.

### Beyond Text: Multimodal Models

LLMs today are not limited to just text. Many models are **multimodal**, meaning they can also work with:

- Images
- Audio
- Video

These are explored in later parts of the course, along with working with other providers like **Anthropic**.

## Quick Summary

| Concept | Meaning |
|---|---|
| `@RestController` | Marks a class as a controller that handles web requests and returns data |
| `@GetMapping("/path")` | Maps a GET request at the given path to a method |
| `@PathVariable` | Captures a value from the URL and passes it into the method |
| `ChatModel` | Spring AI's abstraction to talk to a specific LLM provider (example: OpenAI) |
| `chatModel.call(message)` | Sends a plain text message to the LLM and returns its text response |
| `ChatClient` | A more advanced way to interact with LLMs (covered later) |

## Practice Questions

**Q1: Why did the very first request to `/what is Java` return a 404 error?**
A: Because there was no controller in the backend to handle that request.

**Q2: What does `@PathVariable` do in a Spring controller method?**
A: It captures a value from the URL path and passes it into the method as a parameter.

**Q3: Which class from Spring AI is used to directly talk to the OpenAI model, and which package does it come from?**
A: `ChatModel`, from the `org.springframework.ai.openai` package (made available through the OpenAI starter dependency).

**Q4: How is the `ChatModel` object created and given to the controller?**
A: Spring creates it automatically and injects it into the controller through the constructor (Constructor Injection) — we do not create it manually.

**Q5: What is the simplest way to send a plain text message to the LLM using `ChatModel`?**
A: By calling `chatModel.call(message)`, where `message` is a `String` containing the prompt.

**Q6: What is a limitation of using `chatModel.call(message)` with a plain String?**
A: It does not give much control — for example, you cannot easily send a system message, build a structured prompt, or work with metadata. For that, `ChatClient` is used instead.
