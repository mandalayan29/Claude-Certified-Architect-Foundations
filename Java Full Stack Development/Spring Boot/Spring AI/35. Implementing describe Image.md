## Step 3: Understanding the Challenge — Sending Both Text AND an Image

So far, whenever we used `ChatClient`, we simply passed a plain text string into `.prompt(...)`. But this time, we need to send **both a text query and an image** together — and there's no simple, single-string way to do that.

### Introducing `.prompt()`'s System and User Methods

When working with `ChatClient`, the `.prompt()` chain actually supports more advanced configuration through two special methods:

- **`.system(...)`** → lets you (the developer) set contextual instructions for the AI — essentially telling it how to behave or what context to keep in mind, independent of what the actual user typed
- **`.user(...)`** → represents the message coming from the actual user — this is where the user's query goes

```
.prompt()
   |
   |--- .system(...)  --> Developer-defined context/instructions for the AI
   |--- .user(...)    --> The actual user's message/query
```

> **Why this matters here:** To attach an **image** to our request, we specifically need to use the `.user(...)` method — this is where both the text query and the image get combined together.

## Step 4: Using `.user(...)` with a Consumer (Lambda Expression)

The `.user(...)` method can accept different types of input — including a plain `String`, a `Resource`, or (what we need here) a **`Consumer`** object.

> A `Consumer` is a **functional interface** in Java — meaning it represents a single method (`accept`) that takes an input and does something with it. This lets us use a **lambda expression** to configure multiple things (both text and image) together, cleanly.

### Building the User Spec

```java
String response = chatClient
        .prompt()
        .user(us -> us
                .text(query)
                .media(MimeTypeUtils.IMAGE_JPEG, file.getResource())
        )
        .call()
        .content();
```

**Explanation, step by step:**

- `us -> us...` → this is our lambda expression; `us` represents the **`PromptUserSpec`** object, which lets us configure the user's message in detail
- `.text(query)` → sets the actual text portion of the user's message (our `query` variable, example: "name the superhero")
- `.media(...)` → this is how we attach the **image** to the message. It requires two things:
  - **Media type** → what kind of file we're sending (example: JPEG image)
  - **Resource** → the actual file content, wrapped as a `Resource` object

### Setting the Media Type

```java
MimeTypeUtils.IMAGE_JPEG
```

**Explanation:**

- `MimeTypeUtils` → a utility class that provides predefined constants for common file/media types
- `IMAGE_JPEG` → tells Spring AI we're sending a JPEG image (other options exist too, example: `IMAGE_PNG`, if you're working with PNG files instead)

### Converting `MultipartFile` to `Resource`

There's one small technical detail to handle: `.media(...)` expects a `Resource` object, but our uploaded file is a `MultipartFile` — these are **not the same type**.

**Fix:**

```java
file.getResource()
```

**Explanation:**

- `.getResource()` → a convenient method on `MultipartFile` that converts it into a proper `Resource` object, which is exactly what `.media(...)` needs

## Full Example Code

```java
@RestController
public class ImageGenController {

    private ChatClient chatClient;
    private OpenAiImageModel openAiImageModel;

    // constructor omitted for brevity (same pattern as earlier topics)

    @PostMapping("/image/describe")
    public String describeImage(
            @RequestParam String query,
            @RequestParam MultipartFile file) {

        String response = chatClient
                .prompt()
                .user(us -> us
                        .text(query)
                        .media(MimeTypeUtils.IMAGE_JPEG, file.getResource())
                )
                .call()
                .content();

        return response;
    }
}
```

## How This All Fits Together (Vision Models)

```
User uploads:
   - An image file
   - A text query (specific question OR general "describe this")
        |
        v
Our controller receives both (query as String, file as MultipartFile)
        |
        v
ChatClient.prompt().user(...) combines:
   - The text query
   - The image (converted to a Resource, with its media type specified)
        |
        v
Sent together to the AI model (which supports "vision" — understanding images)
        |
        v
AI analyzes the image based on the query, and returns a text response
```

> This capability — where an AI model can understand and reason about images, not just text — is often referred to as **"vision"** capability in AI models.

## Quick Summary

| Concept | Meaning |
|---|---|
| `.system(...)` | Sets developer-defined context/instructions for the AI (independent of the user's actual message) |
| `.user(...)` | Represents the user's actual message; can accept a `Consumer` for advanced configuration (text + media together) |
| `Consumer` (lambda) | A functional interface used here to configure both text and media on the user's message in one step |
| `.text(query)` | Sets the text portion of the user's message |
| `.media(mediaType, resource)` | Attaches a file (like an image) to the user's message, along with its media type |
| `MimeTypeUtils.IMAGE_JPEG` | A predefined constant representing the JPEG image media type |
| `file.getResource()` | Converts a `MultipartFile` into a `Resource` object, as required by `.media(...)` |

## Practice Questions

**Q1: Why couldn't we simply use `.prompt(text)` (a plain string) to send both a query and an image together?**
A: Because `.prompt(text)` only accepts plain text — it has no way to attach a file/image. To send both text and an image together, we need the more advanced `.user(...)` configuration.

**Q2: What is the difference between `.system(...)` and `.user(...)` when building a prompt?**
A: `.system(...)` sets developer-defined context/instructions for the AI, while `.user(...)` represents the actual message coming from the user (and is where we attach the image in this case).

**Q3: What two pieces of information does `.media(...)` require?**
A: The media type (example: `MimeTypeUtils.IMAGE_JPEG`) and the actual file content, provided as a `Resource` object.

**Q4: Why do we call `.getResource()` on our `MultipartFile` before passing it to `.media(...)`?**
A: Because `.media(...)` expects a `Resource` object, not a `MultipartFile` — `.getResource()` converts the uploaded file into the correct type.

**Q5: What term is commonly used to describe an AI model's ability to understand and analyze images (not just text)?**
A: "Vision" capability.
