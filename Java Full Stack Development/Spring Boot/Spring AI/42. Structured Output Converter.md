# Introduction to Structured Output Converters

## The Problem: AI Normally Talks in Plain Text

When we use tools like **ChatGPT** or **Gemini** as humans, we're used to getting responses back as plain, conversational **text**. This makes sense — these tools are designed to feel like talking to a person.

But when you're doing **AI engineering** — meaning, building an application that talks to an AI model as part of its own logic — plain conversational text often isn't good enough.

### Why Plain Text Isn't Enough for Applications

Imagine two applications talking to each other: **your application**, and the **AI model**. For your application to actually *use* the AI's response programmatically (instead of just displaying it to a human), it usually needs the data in a **predictable, structured format** — such as:

- **JSON data**
- A **list** of values
- A **map** of key-value pairs
- Even a single, specific value (like one word or one letter)

```
Human <--> AI:
   "Tell me a joke" --> "Why did the..." (plain text response is fine)

Application <--> AI:
   "Give me product categories" --> ["Electronics", "Books", "Toys"] (structured data needed!)
```

This is exactly the problem that **Structured Output Converters** solve.

## What Are Structured Output Converters?

Spring AI provides a set of built-in converters that help transform the AI's raw response into a **structured, usable format** in your Java code — instead of just a plain `String`.

### Available Converters

According to Spring AI's documentation, some of the available converters include:

| Converter | Purpose |
|---|---|
| **Bean Output Converter** | Converts the AI's response directly into an existing **Java object (bean)**, filling in its fields/variables |
| **List Output Converter** | Converts the AI's response into a **`List`** of values |
| **Map Output Converter** | Converts the AI's response into a **`Map`** of key-value pairs |

> We'll start with the **List Output Converter** in the next topic, then move on to explore the **Bean Output Converter**.

## How Structured Output Converters Work (The Big Picture)

```
1. You have raw input (your request/data)
        |
        v
2. This goes into a Prompt Template, which builds the actual prompt
        |
        v
3. The prompt is sent to the LLM
        |
        v
4. The LLM returns a RAW output (still just text/data from the model)
        |
        v
5. You apply the appropriate CONVERTER to this raw output
        |
        v
6. You get a properly STRUCTURED output (List, Map, or a specific Java object)
```

## An Important Detail: The LLM Needs to Know What Format You Expect

Here's a crucial point: **you can't simply take any random response from the LLM and expect a converter to magically structure it correctly.**

> For structured output conversion to actually work well, you need to **inform the LLM** ahead of time about the exact format you're expecting — so that what the model generates actually **matches** what your chosen converter is designed to parse.

In other words, there's a bit of **coordination** involved:

```
You tell the LLM: "Please respond in THIS specific format"
        |
        v
The LLM generates output that (hopefully) follows that format
        |
        v
Your chosen converter successfully parses that output into structured data
```

> This coordination between the prompt (telling the LLM what format to use) and the converter (parsing that expected format) is really the core idea behind how structured output converters work — and we'll see exactly how this is done in the upcoming topics.

## Practice Questions

**Q1: Why is plain text often not good enough when an application (rather than a human) is talking to an AI model?**
A: Because applications typically need predictable, structured data (like JSON, a list, or a map) to actually use the AI's response programmatically, rather than just displaying conversational text to a person.

**Q2: Name the three structured output converters mentioned in this topic.**
A: Bean Output Converter, List Output Converter, and Map Output Converter.

**Q3: What does the Bean Output Converter specifically do?**
A: It converts the AI model's response directly into an existing Java object (bean), filling in that object's fields/variables with the appropriate values.

**Q4: Why can't you simply apply any converter to any random LLM response and expect it to work correctly?**
A: Because the LLM needs to be informed ahead of time about the exact format you expect, so that what it generates actually matches the structure the chosen converter is designed to parse.

**Q5: In the overall flow described, what happens between generating the prompt and getting the final structured output?**
A: The prompt is sent to the LLM, which returns a raw output; a converter is then applied to this raw output to transform it into the final structured format (List, Map, or object).
