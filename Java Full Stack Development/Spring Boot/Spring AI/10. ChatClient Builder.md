# Creating ChatClient: Builder vs Programmatic Approach

## What We Have Done So Far

Until now, we created our `ChatClient` object **programmatically**, using `ChatClient.create()` along with an injected `ChatModel`:

```java
public OpenAIController(ChatModel chatModel) {
    this.chatClient = ChatClient.create(chatModel);
}
```

This works perfectly fine. But if you check the **official Spring AI documentation**, you will notice it actually recommends another approach too: using **`ChatClient.Builder`**.

## Two Ways to Create a ChatClient

According to the Spring AI documentation, there are **two ways** to create a `ChatClient`:

| Approach | How It Works |
|---|---|
| **`ChatClient.Builder`** | Spring Boot **auto-configures** this for you automatically |
| **Programmatic (`ChatClient.create(chatModel)`)** | You manually create it yourself, using a `ChatModel` |

We have only used the **programmatic** approach so far. Let's now understand the **Builder** approach and compare both.

## Understanding `ChatClient.Builder`

`ChatClient.Builder` is **auto-configured** by Spring Boot. This means:

- If your application uses **only one model/provider** (example: only OpenAI, or only Anthropic, or only Ollama), Spring Boot can **automatically detect** which model is available in your project (based on your dependencies)
- It will then configure and inject a ready-to-use `ChatClient.Builder` for you
- You don't need to manually pass a `ChatModel` yourself

```
Only one AI dependency in project (example: OpenAI)
        |
        v
Spring Boot auto-detects it
        |
        v
ChatClient.Builder is automatically configured and available for injection
```

## When Should You Use Which Approach?

This is the key decision point:

| Situation | Recommended Approach |
|---|---|
| You are using **only one** AI model/provider in your project | Use **`ChatClient.Builder`** (simpler, auto-configured) |
| You are using **multiple** AI models/providers in the same project | Use the **programmatic approach** (`ChatClient.create(chatModel)`), since the builder alone cannot decide *which* model to use when there are many |

> **Why?** If you have multiple models (example: OpenAI **and** Anthropic) in the same project, Spring Boot cannot automatically know which one you want the `ChatClient.Builder` to use — it could get confused. In that case, it's better to programmatically create separate `ChatClient` objects using specific `ChatModel` instances (one for each provider).

> **Note:** If you do use multiple models and choose the programmatic approach, it is also considered good practice (though not compulsory) to **disable the auto-configured `ChatClient.Builder`**, to avoid any confusion in your project.

## Trying Out `ChatClient.Builder`

Since our current project only uses **OpenAI**, let's try switching to the `ChatClient.Builder` approach to see how it works.

### Step 1: Temporarily Remove the Programmatic Code

Let's comment out our existing programmatic line:

```java
// this.chatClient = ChatClient.create(chatModel);
```

### Step 2: Restart and Test (Expected Failure)

If you restart the application now and send a request, you will get an error:

```
500 Internal Server Error
```

Checking the logs, you will see something like a **`NullPointerException`**, because `chatClient` was never actually created — we only commented out the line that built it, but did not replace it with anything yet.

> This error is **expected** at this stage — it confirms that our `chatClient` object truly depends on that line of code.

### Step 3: Use `ChatClient.Builder` Instead

Now let's fix this by injecting a `ChatClient.Builder` instead of manually creating the client:

```java
@RestController
public class OpenAIController {

    private final ChatClient chatClient;

    public OpenAIController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    // rest of the controller remains the same
}
```

**Explanation:**

- `ChatClient.Builder builder` → Spring Boot automatically injects this, since we only have **one** AI model dependency (OpenAI) in our project
- `builder.build()` → builds and returns a ready-to-use `ChatClient` object
- We no longer need to manually pass a `ChatModel` ourselves in this case

### Step 4: Test Again

1. Restart the application
2. Send the same request through Insomnia (or your API client)

**Result:** It works correctly, and you get a proper AI-generated response, just like before.

> The response text itself may look repetitive at times (example: the AI giving the same joke again even when asked for a "fresh" one) — this is just a normal behavior/limitation of the AI model itself, not related to our `ChatClient.Builder` setup.

## Comparing Both Approaches Side by Side

```java
// Approach 1: Programmatic (using ChatModel directly)
public OpenAIController(ChatModel chatModel) {
    this.chatClient = ChatClient.create(chatModel);
}

// Approach 2: Using ChatClient.Builder (auto-configured)
public OpenAIController(ChatClient.Builder builder) {
    this.chatClient = builder.build();
}
```

| Aspect | Programmatic (`ChatClient.create`) | Builder (`ChatClient.Builder`) |
|---|---|---|
| Setup | You manually pass a `ChatModel` | Auto-configured by Spring Boot |
| Best for | Multiple models/providers in one project | Only one model/provider in the project |
| Code | Slightly more explicit | Simpler, less code |
| Risk of confusion with multiple models | No (you control exactly which model is used) | Yes (not recommended for multiple models) |

## Which One Should You Use Going Forward?

- If your project uses **only one AI provider**, prefer the simpler **`ChatClient.Builder`** approach
- If your project uses **multiple AI providers**, use the **programmatic** approach with specific `ChatModel` instances

> Since this course will later explore multiple providers, both approaches are useful to know — but for a single-model project, the Builder approach is generally the cleaner choice.

## Quick Summary

| Concept | Meaning |
|---|---|
| `ChatClient.create(chatModel)` | Manually creates a `ChatClient` using a specific `ChatModel` — good for multiple providers |
| `ChatClient.Builder` | Auto-configured by Spring Boot — good when only one provider is used |
| `builder.build()` | Builds and returns a ready-to-use `ChatClient` object from the builder |
| NullPointerException (in this context) | Happens if `chatClient` is never actually created/assigned before being used |

## Practice Questions

**Q1: What are the two ways to create a `ChatClient` object, according to the Spring AI documentation?**
A: Programmatically using `ChatClient.create(chatModel)`, or using the auto-configured `ChatClient.Builder`.

**Q2: When is it recommended to use `ChatClient.Builder` instead of the programmatic approach?**
A: When your project uses only one AI model/provider, since Spring Boot can automatically detect and configure it without confusion.

**Q3: Why is the programmatic approach (`ChatClient.create(chatModel)`) preferred when using multiple AI providers?**
A: Because with multiple providers, Spring Boot cannot automatically decide which model the `ChatClient.Builder` should use, so you need to explicitly create clients using specific `ChatModel` instances.

**Q4: What error occurred when the programmatic `ChatClient.create()` line was commented out without replacing it, and why?**
A: A `NullPointerException` (shown as a 500 Internal Server Error), because the `chatClient` field was never actually assigned any object before being used.

**Q5: How do you create a `ChatClient` using the Builder approach?**
A: By injecting `ChatClient.Builder` into the constructor and calling `builder.build()` to get a ready-to-use `ChatClient` object.
