# Implementing Text-to-Speech (Basic Version)

## Goal

Now let's build the opposite of what we just did: converting **text into speech (audio)**.

## Step 1: Planning the Request

Let's plan how we'll test this using Insomnia.

- **URL:** `http://localhost:8080/api/tts`
- **Method:** `POST`
- **Parameter:** `text` → the text we want converted into speech

Since we're not sending a file this time (just text), we don't need multipart form data — a simple request parameter works fine.

**Example value for `text`:** You could use any text, including the output from an earlier transcription/RAG example — for instance, a product description like the ones we generated in earlier topics.

## Step 2: Deciding the Return Type

This is an interesting design question: **what type should our method return, since we're generating audio?**

> Java doesn't have a built-in "speech" or "audio" data type. So how do we represent generated audio in code?

**Answer:** We return a **`byte[]`** (byte array) — since audio data, like any binary file, can be represented as a sequence of bytes.

```java
@PostMapping("/api/tts")
public byte[] textToSpeech(@RequestParam String text) {
    return null; // placeholder for now
}
```

## Step 3: Introducing `OpenAiAudioSpeechModel`

For **transcription** (speech-to-text), we used `OpenAiAudioTranscriptionModel`. For **text-to-speech**, there's a **different, dedicated model**: `OpenAiAudioSpeechModel`.

```
Audio Models (OpenAI):
   |
   |--- OpenAiAudioTranscriptionModel  --> Speech-to-Text
   |--- OpenAiAudioSpeechModel         --> Text-to-Speech
```

### Injecting It

Just like every other model we've used throughout this course, we let Spring inject this for us via the constructor:

```java
private OpenAiAudioSpeechModel audioSpeechModel;

public AudioGenController(
        OpenAiAudioTranscriptionModel audioModel,
        OpenAiAudioSpeechModel audioSpeechModel) {
    this.audioModel = audioModel;
    this.audioSpeechModel = audioSpeechModel;
}
```

## Step 4: Calling the Speech Model

Generating speech turns out to be refreshingly simple:

```java
byte[] audioBytes = audioSpeechModel.call(text);
return audioBytes;
```

**Explanation:**

- `.call(text)` → sends our text directly to OpenAI's speech model
- It returns a `byte[]` directly — exactly the format we need for our method's return type

## Full Example Code

```java
@RestController
public class AudioGenController {

    private OpenAiAudioTranscriptionModel audioModel;
    private OpenAiAudioSpeechModel audioSpeechModel;

    public AudioGenController(
            OpenAiAudioTranscriptionModel audioModel,
            OpenAiAudioSpeechModel audioSpeechModel) {
        this.audioModel = audioModel;
        this.audioSpeechModel = audioSpeechModel;
    }

    @PostMapping("/api/tts")
    public byte[] textToSpeech(@RequestParam String text) {
        return audioSpeechModel.call(text);
    }
}
```

## Step 5: A Practical Challenge — Viewing/Hearing the Result in Insomnia

Here's an interesting real-world consideration: since we're testing with **Insomnia** (a REST API client), and Insomnia is designed primarily to display **text, JSON, or raw data** — not to natively play audio — we need a small workaround to actually **hear** our generated speech.

> **In a real application:** This wouldn't be a problem at all. For example, in a React (or any front-end) application, you could pass this byte array data directly into an audio player component, or embed it in an HTML `<audio>` element, and it would just play normally for the user.

### The Workaround for Testing in Insomnia

1. Send the request as usual
2. Once you receive the response (raw byte data representing the audio), look for an option like **"Export Raw Response"** (the exact option name may vary slightly depending on your REST client)
3. Save this exported file, making sure to give it the correct **file extension** — in this case, **`.mp3`**

```
API Response (raw bytes)
        |
        v
Export/Save as a file
        |
        v
Make sure the file has a .mp3 extension
        |
        v
Open/play the file with any media player
```

> **Common mistake to avoid:** If you forget to add the `.mp3` extension when saving, most media players won't know how to open/play the file correctly — so double-check this step.

## Step 6: Testing the Result

After correctly saving the exported audio as an `.mp3` file, playing it back confirms that the text was successfully converted into **natural-sounding spoken audio**, accurately reading out the original text content (in this example, a product description).

## Two Noticeable Limitations (To Be Addressed Next)

While the basic text-to-speech conversion works well, two things stand out as areas for improvement:

1. **Voice selection** → Currently, we have no control over which "voice" is used. Similar to how voice assistants on phones let you pick between different voice styles, we'd like that same flexibility here.
2. **Speed** → The generated speech, by default, sounds relatively **slow** — it would be nice to control the playback speed (example: speeding it up to `1.5x`).

## Practice Questions

**Q1: Why does the text-to-speech method return a `byte[]` instead of a more specific "audio" type?**
A: Because Java doesn't have a built-in data type for audio/speech — audio data, like other binary files, is naturally represented as a sequence of bytes.

**Q2: Which Spring AI class is used specifically for OpenAI-based text-to-speech, and how is it different from the transcription model?**
A: `OpenAiAudioSpeechModel`, which is different from `OpenAiAudioTranscriptionModel` — one converts text into speech, while the other converts speech into text.

**Q3: What does calling `audioSpeechModel.call(text)` return?**
A: A `byte[]` (byte array) containing the generated audio data.

**Q4: Why couldn't the generated audio be played directly within Insomnia, and what workaround was used instead?**
A: Because Insomnia is designed to display text, JSON, or raw data — not to play audio natively. The workaround was to export/save the raw response as a file, making sure to give it a `.mp3` extension, and then play it with a regular media player.

**Q5: What two limitations were identified with the basic text-to-speech implementation, to be addressed in the next topic?**
A: The inability to choose a specific voice, and the inability to control the playback speed of the generated speech (which sounded relatively slow by default).
