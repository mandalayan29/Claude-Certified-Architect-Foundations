- Both are stored as `float[]` arrays, since embeddings are lists of floating-point numbers

## Step 4: Implementing the Cosine Similarity Formula

Recall from the previous topic, cosine similarity needs three main components:

1. **Dot Product** — combining the two vectors together
2. **Norm (magnitude) of vector 1** — essentially, its "length"
3. **Norm (magnitude) of vector 2** — its "length"

**Formula:**

```
Cosine Similarity = Dot Product / (Norm1 × Norm2)
```

### Code Implementation

```java
double dotProduct = 0.0;
double norm1 = 0.0;
double norm2 = 0.0;

for (int i = 0; i < embedding1.length; i++) {
    dotProduct += embedding1[i] * embedding2[i];
    norm1 += Math.pow(embedding1[i], 2);
    norm2 += Math.pow(embedding2[i], 2);
}

double similarity = dotProduct / (Math.sqrt(norm1) * Math.sqrt(norm2));

return similarity;
```

**Explanation, step by step:**

- **`dotProduct += embedding1[i] * embedding2[i]`** → for every matching pair of numbers (one from each embedding, at the same position `i`), we multiply them together and keep adding the result. This is the "dot product" calculation.
- **`norm1 += Math.pow(embedding1[i], 2)`** → we square each value from `embedding1` and add them all up — this gives us the "sum of squares" needed to calculate the magnitude (norm) of `embedding1`
- **`norm2 += Math.pow(embedding2[i], 2)`** → same idea, but for `embedding2`
- **`Math.sqrt(norm1)`** and **`Math.sqrt(norm2)`** → taking the square root of the sum of squares gives us the actual magnitude (length) of each vector
- **Final formula:** `dotProduct / (Math.sqrt(norm1) * Math.sqrt(norm2))` → this matches exactly what we learned in the theory — dot product divided by the multiplication of both magnitudes

> **Why the loop?** Since embeddings usually have **many dimensions** (sometimes 1000+), we need to repeat this calculation across **every single value** in the vector — this is exactly the "summation across dimensions" concept we discussed in the previous topic.

## Full Example Code

```java
@RestController
public class OpenAIController {

    @Autowired
    @Qualifier("openAiEmbeddingModel")
    private EmbeddingModel embeddingModel;

    @PostMapping("/api/similarity")
    public double getSimilarity(
            @RequestParam String text1,
            @RequestParam String text2) {

        float[] embedding1 = embeddingModel.embed(text1);
        float[] embedding2 = embeddingModel.embed(text2);

        double dotProduct = 0.0;
        double norm1 = 0.0;
        double norm2 = 0.0;

        for (int i = 0; i < embedding1.length; i++) {
            dotProduct += embedding1[i] * embedding2[i];
            norm1 += Math.pow(embedding1[i], 2);
            norm2 += Math.pow(embedding2[i], 2);
        }

        double similarity = dotProduct / (Math.sqrt(norm1) * Math.sqrt(norm2));

        return similarity;
    }
}
```

| Negative values (in some cases) | Opposite meaning (less common in everyday word comparisons) |

## Where Is This Useful? Introducing Semantic Search

This concept of comparing similarity between two pieces of text has a very important real-world use case: **Semantic Search**.

### The Problem with Normal (Keyword) Search

Normally, when you search for something in a document or a list of products, the search works by **matching exact words**. If the exact word isn't present, you get "no results found" — even if something very related actually exists.

**Example:**

- You search for: `"headphones"`
- Your product list contains: `"Bluetooth AirPods"`, `"Wireless Speaker"`

A traditional keyword search would find **nothing**, because the word `"headphones"` doesn't literally appear anywhere in the list — even though `"Bluetooth AirPods"` is clearly a very related/relevant product.

### How Semantic Search Solves This

```
Traditional Search:
   "headphones" --> looks for exact word match --> No results (even if related items exist)

Semantic Search (using embeddings):
   "headphones" --> converted to embedding
        |
        v
   Compared against embeddings of all products (using cosine similarity)
        |
        v
   Finds "Bluetooth AirPods" as a close match, even without exact wording
```

By comparing **embeddings** instead of exact words, semantic search can find results that are **conceptually related**, even if the exact search term never appears in the data.

> This is exactly where the similarity calculation we just built becomes genuinely useful — and it sets the foundation for topics coming up next, where we explore how to search across a larger set of data using this same idea.

## Quick Summary

| Concept | Meaning |
|---|---|
| Dot Product | Multiplying matching values from two vectors and summing the results |
| Norm (Magnitude) | The "length" of a vector, calculated using the square root of the sum of squares of its values |
| Cosine Similarity Formula | `dotProduct / (norm1 × norm2)` |
| Score range | Closer to `1` = very similar; closer to `0` = unrelated |
| Semantic Search | Searching based on meaning/relatedness (using embeddings), instead of exact word matching |

## Practice Questions

**Q1: What three main components are needed to calculate cosine similarity between two embeddings?**
A: The dot product of the two vectors, and the norm (magnitude) of each individual vector.

**Q2: Why is a loop needed when calculating cosine similarity for real embeddings?**
A: Because embeddings often have many dimensions (sometimes 1000+ values), and the calculation (dot product and norms) must be performed across every single value/dimension, then summed together.

**Q3: What does a cosine similarity score close to `1` indicate? What about close to `0`?**
A: Close to `1` indicates the two pieces of text are very similar/closely related. Close to `0` indicates they are largely unrelated.

**Q4: What is the main limitation of traditional keyword-based search that semantic search solves?**
A: Traditional keyword search only finds exact word matches, so it misses conceptually related results if the exact search term doesn't appear in the data. Semantic search (using embeddings) can find related results based on meaning, even without exact wording.

**Q5: How can you convert a cosine similarity score (a decimal between 0 and 1) into a percentage?**
A: By multiplying the resulting similarity value by `100`.
