# Implementing the List Output Converter

## Goal

Let's implement our first structured output converter: the **List Output Converter**. We'll build a feature that returns a `List<String>` of movie names for a given actor — not just a plain text response.

## Step 1: Create a New Controller

Let's create a dedicated `MovieController` for this feature.

```java
@RestController
public class MovieController {

    private ChatClient chatClient;

    public MovieController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }
}
```

> **Note:** Unlike some earlier controllers, this one only needs a `ChatClient` — there's no need for `VectorStore`, `EmbeddingModel`, or any `@Qualifier` here, since we're only doing simple prompt-based generation this time.

## Step 2: Planning the Method

We want a method that:

- Accepts an actor's name
- Returns a `List<String>` of that actor's top movies

```java
@GetMapping("/movies")
public List<String> getMovies(@RequestParam String name) {
    return null; // placeholder for now
}
```

**Explanation:**

- `@GetMapping("/movies")` → maps this method to handle `GET` requests at `/movies`
- `@RequestParam String name` → captures the actor's name from the request
- **Return type `List<String>`** → this is the key difference from before — we want a proper `List`, not a plain `String`

## Step 3: Writing the Prompt Message

```java
String message = "List top five movies of {name}\n{format}";
```

**Explanation:**

- `{name}` → a placeholder for the actor's name (just like we did with `PromptTemplate` earlier in the course)
- `{format}` → a **new** placeholder — this is where we'll tell the LLM exactly what output format we expect

> **Why do we need `{format}`?** If we simply ask *"list top five movies of X"*, the LLM might respond with extra details, explanations, or inconsistent formatting. By explicitly telling it the exact format we want, we make its response much more predictable — which is essential for our converter to work correctly.

## Step 4: Creating the `ListOutputConverter`

```java
ListOutputConverter outputConverter = new ListOutputConverter(new DefaultConversionService());
```

**Explanation:**

- `ListOutputConverter` → the specific converter class for converting AI responses into a `List`
- `DefaultConversionService` → a required parameter needed to construct the converter; you *can* create your own custom conversion service, but using the **default** one works perfectly fine for our needs here

## Step 5: Getting the Format String from the Converter

Here's the key piece connecting our prompt to our converter: the converter itself can tell us **exactly what format string it expects**.

```java
String format = outputConverter.getFormat();
```

**Explanation:**

- `.getFormat()` → returns a format description (as a `String`) that we can insert directly into our prompt — this ensures the LLM is told to respond in **exactly** the format our converter knows how to parse

## Step 6: Building the Prompt Template

Now we combine our message, the actor's name, and this format string into a `PromptTemplate`, using a `Map` (just like we did in the earlier Prompt Templates topic):

```java
PromptTemplate promptTemplate = new PromptTemplate(
    message,
    Map.of("name", name, "format", outputConverter.getFormat())
);
```

**Explanation:**

- `message` → our template string, containing both `{name}` and `{format}` placeholders
- `Map.of("name", name, "format", outputConverter.getFormat())` → provides the actual values to substitute in for each placeholder

## Step 7: Creating the Prompt and Calling the LLM

```java
Prompt prompt = promptTemplate.create();

String content = chatClient
        .prompt(prompt)
        .call()
        .content();
```

**Explanation:**

- `promptTemplate.create()` → builds the final `Prompt` object, with all placeholders filled in
- `.call().content()` → sends the prompt and gets back a plain `String` response — but remember, this is still just raw text at this point, not yet a structured `List`

## Step 8: Converting the Raw Response into a List

This is the final, crucial step — using our converter to transform the raw text response into an actual `List<String>`:

```java
List<String> movies = outputConverter.convert(content);
return movies;
```

**Explanation:**

- `outputConverter.convert(content)` → takes the raw text response and parses it into a proper `List<String>`, based on the format the LLM was instructed to follow
- Since the LLM's response is expected to match the format our converter understands, this conversion should work smoothly

> **Note:** Your IDE might show a warning here about a possible `null` return, since `.convert(...)` technically could return `null` in some edge cases — this is a normal, minor warning and doesn't prevent the code from working correctly.

## Full Example Code

```java
@RestController
public class MovieController {

    private ChatClient chatClient;

    public MovieController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/movies")
    public List<String> getMovies(@RequestParam String name) {

        String message = "List top five movies of {name}\n{format}";

        ListOutputConverter outputConverter = new ListOutputConverter(new DefaultConversionService());

        PromptTemplate promptTemplate = new PromptTemplate(
            message,
            Map.of("name", name, "format", outputConverter.getFormat())
        );

        Prompt prompt = promptTemplate.create();

        String content = chatClient
                .prompt(prompt)
                .call()
                .content();

        List<String> movies = outputConverter.convert(content);

        return movies;
    }
}
```

## Why This Matters

> If you're integrating this AI feature into a **larger existing application** — one that expects a `List<String>` to work with (example: to display movie names in a UI dropdown, or process them further in code) — this structured output makes that integration seamless. The calling code doesn't need to do any manual text parsing; it just receives a proper Java `List`, ready to use.

## Recap: The Overall Pattern

```
1. Write your prompt message, including BOTH your actual placeholders (like {name})
   AND a {format} placeholder
        |
        v
2. Create the appropriate OutputConverter (here, ListOutputConverter)
        |
        v
3. Get the expected format string from the converter (.getFormat())
        |
        v
4. Build your PromptTemplate, filling in both your data AND the format string
        |
        v
5. Send the prompt, get back the raw text response
        |
        v
6. Use the converter's .convert(...) method to transform that raw text 
   into your desired structured type (here, List<String>)
```

## Quick Summary

| Concept | Meaning |
|---|---|
| `ListOutputConverter` | Converts an AI's raw text response into a `List<String>` |
| `DefaultConversionService` | The default conversion service required to construct a `ListOutputConverter` (custom ones are also possible) |
| `.getFormat()` | Returns a format description string that should be included in the prompt, telling the LLM exactly how to structure its response |
| `.convert(content)` | Takes the raw text response and parses it into the target structured type (here, `List<String>`) |
| `{format}` placeholder | A placeholder added to your prompt template specifically to insert the converter's expected format instructions |

## Practice Questions

**Q1: Why do we include a `{format}` placeholder in our prompt message, in addition to our actual data placeholders (like `{name}`)?**
A: To explicitly tell the LLM exactly what output format to follow, ensuring its response matches what our converter is designed to parse — without this, the LLM might return inconsistent or extra, unwanted details.

**Q2: What method on `ListOutputConverter` provides the exact format string that should be inserted into the prompt?**
A: `.getFormat()`

**Q3: What does `outputConverter.convert(content)` actually do?**
A: It takes the raw text response received from the LLM and parses/converts it into the target structured type — in this case, a `List<String>`.

**Q4: What object is required to construct a `ListOutputConverter`, and what is the simplest option to use?**
A: A conversion service object; the simplest option is to use `new DefaultConversionService()`.

**Q5: Why is returning a `List<String>` (instead of a plain `String`) particularly useful when integrating AI into an existing application?**
A: Because the calling code can work directly with a proper Java `List`, without needing to manually parse or split text — making the AI feature much easier to integrate seamlessly into existing application logic.
