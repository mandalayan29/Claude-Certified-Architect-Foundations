# Setting Up Speech-to-Text: Planning and Controller Setup

## Goal

In this topic, we start implementing **speech-to-text (transcription)** — sending an audio file to our application and getting back the transcribed text.

## Step 1: Create a New Controller

Just like we created a dedicated `ImageGenController` for image-related features, let's create a separate controller for audio:

```java
@RestController
public class AudioGenController {
    // implementation goes here
}
```

This controller will eventually have **two methods**:

1. **Speech-to-Text** (transcription) — covered in this topic
2. **Text-to-Speech** — covered in a later topic

## Step 2: Planning the Speech-to-Text Method

```java
@PostMapping("/api/stt")
public String speechToText() {
    return "";
}
```

**Explanation:**

- `@PostMapping("/api/stt")` → maps this method to handle `POST` requests at `/api/stt` (short for **S**peech-**T**o-**T**ext — since "STT" is a more fitting short form here than "TTS," which is typically reserved for **T**ext-**T**o-**S**peech)
- **Return type `String`** → since we expect the transcribed text back
- For now, we return an empty string as a placeholder, just to avoid errors while we build this out step by step

## Step 3: Planning the Request Using an API Client

Let's plan how we'll test this using Insomnia (or a similar tool).

### Basic Setup

- **URL:** `http://localhost:8080/api/stt`
- **Method:** `POST`

### Sending the Audio File

Just like we did with image uploads earlier in the course, sending an audio file requires using **multipart form data**:

1. Go to the **Body** section
2. Select **Form Data** (making sure the request type is **multipart**)
3. Add a field (example: named `file`)
4. Set its type to **File**
5. Choose the actual audio file you want to transcribe

```
Request Body (Form Data):
   |
   |--- file  --> [Selected audio file to transcribe]
```

> **Optional:** You could also send additional text alongside the audio (example: extra instructions), but for this first pass, we'll focus purely on the audio itself.

### About the Test Audio Files Used

For testing, a few different audio files were used, including:

- A recording of part of an actual course video (around 11–12 minutes long)
- An **AI-generated voice** clip, created by giving a text-to-speech model this text: *"You are a language translator. Translate the English text to Hindi now."*

> This second example is a nice, natural bridge — it shows that these AI audio capabilities can even be used to **create your own test audio**, which you can then feed back into a transcription model to test the "round trip" (text → speech → text again).

### First Test (Expected to Not Work Yet)

At this point, if you send this test request:

1. **First issue:** If the server isn't running yet, you'll simply get a connection error
2. **After starting the server:** You'll get "no response," because:
   - We are **not yet accepting** the uploaded file in our method (no parameter defined for it)
   - We are **not yet returning** anything meaningful (just an empty string)

> This is expected — we've only created the basic method structure so far. The actual logic still needs to be added.

## Step 4: Preparing to Use the Audio Transcription Model

Before completing the actual transcription logic, we need to set up the model we'll use: **`OpenAiAudioTranscriptionModel`**.

### Creating the Object via Constructor Injection

Just like with `ChatModel`, `EmbeddingModel`, and `OpenAiImageModel` earlier in the course, we don't create this object manually ourselves — we let **Spring inject it** for us.

```java
@RestController
public class AudioGenController {

    private OpenAiAudioTranscriptionModel audioModel;

    public AudioGenController(OpenAiAudioTranscriptionModel audioModel) {
        this.audioModel = audioModel;
    }

    @PostMapping("/api/stt")
    public String speechToText() {
        return "";
    }
}
```

**Explanation:**

- `OpenAiAudioTranscriptionModel audioModel` → this is the specific Spring AI class responsible for handling **speech-to-text transcription** using OpenAI
- Just like other models we've used throughout this course, Spring automatically creates and injects this object into our controller's constructor — we don't need to build it manually
- This works right away because we already have the **OpenAI dependency** set up from much earlier in the course — no additional dependency was needed

## What's Next

With our controller structure and the `OpenAiAudioTranscriptionModel` now in place, the next topic will complete the implementation: accepting the uploaded audio file, sending it to the transcription model, and returning the actual transcribed text.

## Quick Summary

| Concept | Meaning |
|---|---|
| `AudioGenController` | A new, dedicated controller created for audio-related features (transcription and text-to-speech) |
| `/api/stt` | Our planned endpoint for speech-to-text (transcription) |
| Multipart form data | The request format used to send an audio file, similar to how we sent images earlier |
| `OpenAiAudioTranscriptionModel` | Spring AI's class for performing speech-to-text transcription using OpenAI, injected automatically by Spring |

## Practice Questions

**Q1: Why was a new controller (`AudioGenController`) created instead of adding audio methods to an existing controller?**
A: To keep the code organized by feature — similar to how a separate `ImageGenController` was created earlier for image-related functionality.

**Q2: What HTTP method and request format are used to send an audio file for transcription?**
A: A `POST` request, with the audio file sent as multipart form data (similar to how images were uploaded earlier).

**Q3: Why did the first test request return "no response" even after the server was running?**
A: Because the method wasn't yet accepting the uploaded file as a parameter, and it wasn't returning any meaningful content — only an empty string placeholder.

**Q4: Which Spring AI class is used specifically for OpenAI-based speech-to-text transcription?**
A: `OpenAiAudioTranscriptionModel`

**Q5: Why didn't any new dependency need to be added to use `OpenAiAudioTranscriptionModel`?**
A: Because the OpenAI dependency was already added much earlier in the course, and it already includes support for this audio transcription model.
