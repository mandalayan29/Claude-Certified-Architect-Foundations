# Running LLMs Locally with Ollama

## Why Run a Model Locally?

So far, we have been using **OpenAI** as a **service**. This means:

- Our requests go over the internet to OpenAI's servers
- We need an account and an API key
- We need to add money/credits, since it's a paid, cloud-based service

But what if you want to:

- Run an AI model directly on **your own machine** (laptop/desktop)
- Avoid paying for every request
- Freely experiment or modify things locally

This is possible using **open-source models** that can run on your own computer. One of the most popular tools for this is **Ollama**.

## What is Ollama?

**Ollama** is a tool that lets you **get up and running with large language models locally** — directly on your own machine, without needing an internet-based paid service.

With Ollama, you can run models like:

- Llama
- DeepSeek
- Phi
- Mistral
- Gemma
- and several others

> You can browse the full list of available models on Ollama's website, and even search for a specific one you're interested in.

> **Note:** Among these, **Mistral** is the model that Spring AI tends to pick up by default in certain setups — this will be shown later.

## Step 1: Install Ollama

1. Go to the official Ollama website
2. Click on **Download**
3. Choose the version based on your operating system (Windows, macOS, Linux)
4. Run the installer (Next → Next → Next → Finish, and accept the agreement)

> **Note:** The download file is fairly large (around **1 GB**), so it may take some time depending on your internet speed.

## Step 2: Verify Ollama Is Installed

Once installed, open a terminal and check if Ollama is available.

**Syntax:**

```
ollama
```

**What it does:** Running this command alone shows Ollama's help/usage information. If you see this output, it confirms Ollama is correctly installed on your machine.

### Checking Installed Models

**Syntax:**

```
ollama list
```

**What it does:** Shows the list of models that are already downloaded on your machine.

> **Note:** If this is your **first time** using Ollama, this list will likely be **empty**, since models are not included by default — each model needs to be downloaded separately, and they can be quite large in size.

## Step 3: Download and Run a Model

To download and run a specific model, you first need to find the correct command for that model from Ollama's **Models** page on their website.

### Example: Running Mistral

**Syntax:**

```
ollama run <model_name>
```

**Example:**

```
ollama run mistral
```

**What this command does:**

1. It first checks if the model (`mistral` in this case) is already downloaded on your machine
2. If it **is** already downloaded, it runs immediately
3. If it is **not** downloaded yet, Ollama will automatically **download** it first, and then run it

Once the model starts running, you will see a prompt like:

```
Send a message:
```

You can now type your question directly in the terminal.

### Example Interaction

```
What is Spring AI?
```

**Response (example):** The model may respond that "Spring AI" does not appear to be an officially recognized term.

### Why Does This Happen?

This happens because of an important limitation of local models:

> Local models are trained on **older, fixed data** (up to a certain point in time). They do not automatically know about newer topics, tools, or terms — unless you specifically train or fine-tune them with your own data.

This is different from cloud-based services like OpenAI or Anthropic, which are often updated more frequently.

### Testing a Simple Prompt

Let's try something simpler:

```
Tell me a joke
```

**Result:** The model responds correctly, giving a programming-related joke.

If you then type:

```
More
```

**Result:** The model correctly understands the context and gives another related joke.

> This shows that, when running directly in the terminal like this, Ollama **already maintains conversation memory by default** for that session — you don't need any extra setup for this basic terminal-based interaction.

## A Note on System Requirements

Different models come in different sizes, and larger models need **more RAM and CPU/GPU power** to run smoothly.

Some example sizes:

| Model | Approx. Size |
|---|---|
| Mistral (7B parameters) | Manageable size for most systems |
| Example model (4.1) | Still manageable |
| DeepSeek (32B version) | Around 20 GB |

### General Advice

```
Try a bigger/more powerful model first
        |
        v
   Does it run smoothly on your system?
        |
   ----- -----
   |         |
  Yes        No
   |         |
  Great!   Try a smaller model instead
```

Choose the model size based on your own system's configuration (RAM, CPU, GPU). If a larger model struggles or fails to run, try a smaller one instead.

## What's Next: Using Ollama Inside Our Code

Now that Ollama is installed and we know how to run a model directly from the terminal, the next step is to actually **use it inside our Spring Boot application** — just like we did with OpenAI.

A few important differences to keep in mind going forward:

- Since the model runs **locally**, we do **not** need an API key (API keys are only needed for cloud-based services like OpenAI)
- We will need a **separate controller**, since our current controller is built specifically to work with **OpenAI**. A new controller (or configuration) will be needed to work with **Ollama/local models** instead.

## Quick Summary

| Command | What It Does |
|---|---|
| `ollama` | Shows Ollama's help/usage info — confirms Ollama is installed |
| `ollama list` | Lists all models already downloaded on your machine |
| `ollama run <model_name>` | Downloads (if needed) and runs the specified model |

| Concept | Meaning |
|---|---|
| Ollama | A tool to run large language models locally on your own machine |
| Local model limitation | Trained on older/fixed data, so may not know newer terms unless specifically trained |
| API key requirement | Not needed for local models (only needed for cloud-based services like OpenAI) |
