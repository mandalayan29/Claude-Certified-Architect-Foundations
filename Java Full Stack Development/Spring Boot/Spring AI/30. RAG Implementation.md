# Implementing RAG Using QuestionAnswerAdvisor

## Goal

Now let's actually implement RAG in our project, so that user questions get answered based on **our own product data**, instead of generic LLM responses.

## Step 1: Create a Basic "Ask" Endpoint (Without RAG Yet)

Let's start by creating a simple endpoint, similar to what we've built before, but without RAG for now — just to see the "before" behavior clearly.

```java
@PostMapping("/api/ask")
public String getAnswerUsingRag(@RequestParam String query) {

    String response = chatClient
            .prompt(query)
            .call()
            .content();

    return response;
}
```

**Explanation:**

- `@PostMapping("/api/ask")` → maps this method to handle `POST` requests at `/api/ask`
- `@RequestParam String query` → captures the user's question from the request
- This is essentially the same pattern we've used before: send the prompt, call the LLM, get the content back — **no RAG involved yet**

## Step 3: Implementing RAG Using `QuestionAnswerAdvisor`

Now here's the interesting part: implementing RAG in Spring AI is surprisingly simple, thanks to **Advisors** (which we first learned about when implementing chat memory).

> Just like we used `MessageChatMemoryAdvisor` to add conversation memory, we can use a different advisor — **`QuestionAnswerAdvisor`** — to add RAG capability.

### Adding the Advisor

```java
String response = chatClient
        .prompt(query)
        .advisors(new QuestionAnswerAdvisor(vectorStore))
        .call()
        .content();
```

**Explanation:**

- `.advisors(...)` → attaches one or more advisors to this specific request
- `new QuestionAnswerAdvisor(vectorStore)` → creates a `QuestionAnswerAdvisor`, and tells it **where to retrieve relevant context from** — in this case, our existing `vectorStore` object (the same one we've already set up and populated with product data in earlier topics)

> **That's it — just one line of code is all it takes to enable RAG here!** This works because we already did all the heavy lifting earlier in the course: loading the product file, breaking it into chunks, generating embeddings, and storing everything in our `VectorStore`.

### How It Works Behind the Scenes

```
User sends a query
        |
        v
QuestionAnswerAdvisor intercepts the request
        |
        v
It searches the VectorStore for relevant chunks 
(using similarity search, just like we did manually before)
        |
        v
It automatically adds these relevant chunks as CONTEXT to the prompt
        |
        v
The enriched prompt (original query + retrieved context) is sent to the LLM
        |
        v
LLM generates a response, grounded in your actual data
```

## Full Example Code

```java
@RestController
public class OpenAIController {

    @Autowired
    private ChatClient chatClient;

    @Autowired
    private VectorStore vectorStore;

    @PostMapping("/api/ask")
    public String getAnswerUsingRag(@RequestParam String query) {

        String response = chatClient
                .prompt(query)
                .advisors(new QuestionAnswerAdvisor(vectorStore))
                .call()
                .content();

        return response;
    }
}
```

## Step 4: Testing With RAG Enabled

### Test 1: Asking About Kids' Art Activities (With RAG)

```
POST http://localhost:8080/api/ask?query=I need a product suggestion for kids art activities
```

**Result:** This time, the AI specifically recommends: *"Art Supplies Kit for Kids"* — the exact matching product from our own data file! This is a huge improvement over the earlier, generic response.

### Test 2: Asking for Details About a Specific Product

```
POST http://localhost:8080/api/ask?query=need details about portable bluetooth speaker
```

**Result:** The AI responds with accurate details about the **Portable Bluetooth Speaker** — mentioning it's compact and lightweight, matching our actual product data.

> **Important detail:** The AI doesn't just copy-paste the raw text from our document — it takes the retrieved context and **rephrases/generates a natural response** based on it. This is still "generation," just now properly **grounded** in real data (hence, Retrieval **Augmented** Generation).

## Why This Matters: Real-World Use Cases

This same RAG pattern is used extensively in real-world AI products:

> Even tools like **ChatGPT** use RAG-like techniques behind the scenes. Since the underlying model itself is only trained up to a certain date, when you ask ChatGPT about very recent information and it responds correctly, that's usually because it's using **external services** (like live web search) to retrieve up-to-date context, then generating a response based on that — the same core idea as RAG.

### RAG Isn't Limited to Text Files

While we used a simple text file in this course, RAG can work with many types of external data sources, including:

- **APIs** (fetching live data from other services)
- **Documents** (not just plain text — also **PDFs**, and other document types)

> For example, if you have a PDF document, Spring AI provides dedicated **PDF readers** that let you extract and process that content, just like we did with our text file, so you can use RAG with PDF-based knowledge sources too.

## Quick Summary

| Concept | Meaning |
|---|---|
| `QuestionAnswerAdvisor` | A Spring AI advisor that implements RAG — automatically retrieves relevant context from a `VectorStore` and adds it to the prompt before sending it to the LLM |
| `.advisors(new QuestionAnswerAdvisor(vectorStore))` | The single line of code needed to enable RAG on a `ChatClient` request, given an existing `VectorStore` |
| RAG in real products | Techniques like RAG are used behind the scenes even in tools like ChatGPT, to provide more current or specific information beyond the model's original training |
| RAG data sources | Not limited to plain text files — can include APIs, PDFs, and other document types |

## Practice Questions

**Q1: What advisor is used in Spring AI to implement RAG (Retrieval Augmented Generation)?**
A: `QuestionAnswerAdvisor`

**Q2: What single piece of information does `QuestionAnswerAdvisor` need in order to work?**
A: A `VectorStore` object, which it uses to search for and retrieve relevant context based on the user's query.

**Q3: Why was implementing RAG relatively simple in this course, requiring just one line of code?**
A: Because all the necessary groundwork — loading the data file, breaking it into chunks, generating embeddings, and storing them in a `VectorStore` — had already been done in earlier topics. `QuestionAnswerAdvisor` simply uses that existing setup.

**Q4: Does the AI response using RAG copy the original document text exactly, or does it generate a new response?**
A: It generates a new, natural-language response, based on (grounded in) the retrieved context — it doesn't just paste the raw document text verbatim.

**Q5: Besides plain text files, what other types of data sources can be used with RAG in Spring AI?**
A: APIs (for live/external data) and other document types, including PDFs (using dedicated document readers).
