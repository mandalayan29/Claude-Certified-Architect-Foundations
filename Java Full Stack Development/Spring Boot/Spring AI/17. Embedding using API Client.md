# Generating Embeddings Using OpenAI's API (via API Client)

## Goal

In the previous topic, we understood **what embeddings are** conceptually. Now, let's actually **generate real embeddings**, using an API client (like Insomnia or Postman) — without writing any Java code yet.

## Step 1: The Embeddings API Endpoint

OpenAI provides a dedicated API endpoint for generating embeddings.

**Endpoint:**

```
POST https://api.openai.com/v1/embeddings
```

> **Important:** Make sure the URL uses `HTTPS` — this endpoint only works over a secure connection.

### First Attempt (No Setup Yet)

If you send a request to this URL without any setup, you will get an error:

```
You didn't provide an API key.
```

This confirms that, just like with chat completions, the **embeddings API also requires authentication**.

## Step 2: Adding the API Key (Authorization Header)

To authenticate, we need to add an **Authorization header** to our request.

**Header format:**

```
Authorization: Bearer <YOUR_API_KEY>
```

**Explanation:**

- `Authorization` → the header name
- `Bearer` → indicates the type of authentication being used (a "Bearer token")
- `<YOUR_API_KEY>` → your actual OpenAI API key (the same one created earlier in this course)

Once this header is added correctly and you send the request again, the "missing API key" error goes away.

## Step 3: Specifying the Model

After fixing the API key issue, you may see a new error:

```
You must provide a model parameter.
```

This means we now need to tell OpenAI **which embedding model** to use. We do this by sending a JSON body with the request.

### Setting Up the Request Body

1. Go to the **Body** section of your request
2. Choose **JSON** as the format
3. (Optional but good practice: also set the `Content-Type: application/json` header)

**Example JSON body (model only):**

```json
{
  "model": "text-embedding-3-large"
}
```

> You can also use `text-embedding-3-small` instead of `text-embedding-3-large`, depending on your needs (smaller = fewer dimensions, faster, usually cheaper).

## Step 4: Specifying the Input Text

After adding the model, sending the request again will show another error:

```
Input is a required property.
```

This means we also need to specify **what text** we want the embedding for.

### Updated JSON Body

```json
{
  "model": "text-embedding-3-large",
  "input": "dog"
}
```

**Explanation:**

- `input` → the actual text you want to convert into an embedding (in this case, the word `"dog"`)

## Step 5: Sending the Request and Viewing the Result

Once both `model` and `input` are provided correctly, sending the request gives you a successful response — containing the **embedding values** for the word `"dog"`.

### What the Response Looks Like

The response contains a **large list of floating-point numbers** — this is the embedding vector.

> As expected from what we learned earlier, this list is **huge** — more than **3,000 values** (matching the dimension count of the `text-embedding-3-large` model, which is 3072 dimensions).

## Step 6: Limiting the Number of Dimensions

A 3072-value list is difficult to work with directly (especially for learning or visualization purposes). Thankfully, OpenAI lets us **limit the number of dimensions**, specifically for the `text-embedding-3-small` and `text-embedding-3-large` models.

### Updated JSON Body (With Limited Dimensions)

```json
{
  "model": "text-embedding-3-large",
  "input": "dog",
  "dimensions": 2
}
```

**Explanation:**

- `dimensions` → tells OpenAI how many numbers you want in the resulting embedding vector (in this case, just `2`)

Now, instead of thousands of values, you get just **2 numbers** back — much easier to understand and visualize (example: as X and Y coordinates on a graph).

## Step 7: Comparing Different Words

Let's try generating 2-dimensional embeddings for a few different words, and compare their values.

### Example: "laptop"

```json
{
  "model": "text-embedding-3-large",
  "input": "laptop",
  "dimensions": 2
}
```

**Example result (illustrative):** Something like `(-0.5, 0.8)`

If you plot this on a graph, it lands in roughly the same area as before (matching what we saw in the visualization from the previous topic).

### Example: "India"

```json
{
  "model": "text-embedding-3-large",
  "input": "India",
  "dimensions": 2
}
```

**Example result (illustrative):** A value like `(-0.9, ...)`, plotted in a different area of the graph — the "countries" region.

### Example: "USA"

```json
{
  "model": "text-embedding-3-large",
  "input": "USA",
  "dimensions": 2
}
```

**Result:** Plotted somewhere near "India" — since both are countries, their embeddings tend to be relatively closer to each other compared to unrelated words (like "laptop").

### Example: "Russia"

```json
{
  "model": "text-embedding-3-large",
  "input": "Russia",
  "dimensions": 2
}
```

**Result:** Plotted **close to "India"** on the graph — again confirming that country names tend to cluster together, away from unrelated topics like technology terms or programming languages.

## Understanding the Limitation of Very Low Dimensions

While using just **2 dimensions** is great for visualization and learning, it has a downside:

> With only 2 dimensions, embeddings can sometimes behave unexpectedly or seem inconsistent, because so much information about the word's meaning has to be "compressed" into just two numbers.

With **higher dimensions** (like the full 3072, or more reasonable/moderate values), the relationships between words tend to be represented much more accurately and reliably.

```
Very low dimensions (e.g. 2)   --> Easy to visualize, but less accurate relationships
Higher dimensions (e.g. 1536+) --> Harder to visualize directly, but far more accurate
```

## Visualizing These Values Yourself

If you want to experiment with plotting embedding values yourself, you can use any simple graphing/plotting tool (example: GeoGebra, or similar tools), and manually enter the X and Y values you get from the API response.

## Quick Summary

|---|---|

| Required header | `Authorization: Bearer <API_KEY>` |
| Required JSON fields | `model` and `input` |
| Optional JSON field | `dimensions` — limits the number of values returned (only works with `text-embedding-3-small`/`3-large`) |

## Practice Questions

**Q1: What is the OpenAI API endpoint used to generate embeddings?**
A: `POST https://api.openai.com/v1/embeddings`

**Q2: How do you authenticate a request to the embeddings API?**
A: By adding an `Authorization` header with the value `Bearer <YOUR_API_KEY>`.

**Q3: What are the two required fields in the JSON body when requesting an embedding?**
A: `model` (which embedding model to use) and `input` (the text you want the embedding for).

**Q4: What does the `dimensions` field do, and which models support it?**
A: It limits how many numbers (dimensions) are returned in the embedding vector. It is only supported by the `text-embedding-3-small` and `text-embedding-3-large` models.

**Q5: Why did embeddings for "India," "USA," and "Russia" plot close to each other, while "laptop" plotted far away?**
A: Because embeddings place conceptually related items (like countries) closer together, and unrelated items (like a country versus a technology product) further apart.

**Q6: What is a downside of using a very low number of dimensions (example: 2) for embeddings?**
A: With very few dimensions, so much meaning has to be compressed into just a couple of numbers that the relationships between words can become less accurate or behave unexpectedly, compared to using higher dimensions.
