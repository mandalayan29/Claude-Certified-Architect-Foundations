# Implementing the Bean Output Converter

## Goal

In the previous topic, we got a `List<String>` of movie names. Now, let's go a step further: getting the AI to return **one full movie object**, with structured fields like name, lead cast, director, and year — as proper **JSON**, mapped directly into a Java class.

## Step 1: Creating the `Movie` Class (Our "Bean")

First, we need a plain Java class representing the structure we want our data in.

```java
public class Movie {

    private String movieName;
    private String leadCast;
    private String director;
    private int year;

    // getters and setters for all fields
}
```

**Explanation:**

- This is a simple **Java bean** — a plain class with private fields and public getters/setters
- **Note:** Lombok (a library that auto-generates getters/setters) was intentionally **not** used here, to keep things straightforward — getters and setters were generated manually (using the IDE's built-in generation feature)
- Each field represents one piece of information we expect back from the AI: the movie's name, lead cast, director, and release year

## Step 2: Planning the Method

We want a method that:

- Accepts an actor's name
- Returns **one** `Movie` object (not a list this time), filled in with real data about one of that actor's movies

```java
@GetMapping("/movie")
public Movie getMovieData(@RequestParam String name) {
    return null; // placeholder for now
}
```

**Explanation:**

- `@GetMapping("/movie")` → notice this is singular (`/movie`), different from the earlier `/movies` endpoint, to avoid confusion
- **Return type `Movie`** → this time, we return our custom class directly, not a `String` or a `List`

## Step 3: Writing the Prompt Message

```java
String message = "Get me the best movie of {name}\n{format}";
```

**Explanation:**

- Very similar to before, but this time we're asking for **the best movie** (singular), not a list of movies
- We still include the `{format}` placeholder — but this time, the format will describe a **JSON object matching our `Movie` class**, not a simple list

## Step 4: Creating the `BeanOutputConverter`

This time, instead of `ListOutputConverter`, we use **`BeanOutputConverter`**.

```java
BeanOutputConverter<Movie> outputConverter = new BeanOutputConverter<>(Movie.class);
```

**Explanation:**

- `BeanOutputConverter` → this converter **implements** the more general `StructuredOutputConverter` interface (the same underlying interface concept behind all these converters, including `ListOutputConverter`)
- `BeanOutputConverter<Movie>` → since this converter needs to know **which specific class** to map the response into, we use **generics** — specifying `Movie` as the target type
- `new BeanOutputConverter<>(Movie.class)` → we also pass `Movie.class` as a constructor argument, explicitly telling the converter which class's structure to expect

> This is an important difference from `ListOutputConverter` — a `List<String>` is generic enough that it doesn't need extra class information, but converting into a **specific custom object** requires telling the converter exactly which class to target.

## Step 5: Getting the Format and Building the Prompt

This part follows the **same pattern** as before:

```java
PromptTemplate promptTemplate = new PromptTemplate(
    message,
    Map.of("name", name, "format", outputConverter.getFormat())
);

Prompt prompt = promptTemplate.create();

String content = chatClient
        .prompt(prompt)
        .call()
        .content();
```

**Explanation:**

- `outputConverter.getFormat()` → this time, it returns a format description matching a **JSON structure for our `Movie` class** (based on its fields), rather than a simple list format
- The rest of the flow — building the template, creating the prompt, calling the LLM — is identical to what we did with the List Output Converter

## Step 6: Converting the Response into a `Movie` Object

```java
Movie movie = outputConverter.convert(content);
return movie;
```

**Explanation:**

- `outputConverter.convert(content)` → takes the raw JSON-like text response from the LLM, and parses/maps it directly into a properly populated `Movie` object — with `movieName`, `leadCast`, `director`, and `year` all filled in

## Full Example Code

```java
public class Movie {
    private String movieName;
    private String leadCast;
    private String director;
    private int year;

    // getters and setters
}
```

```java
@RestController
public class MovieController {

    private ChatClient chatClient;

    public MovieController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping("/movie")
    public Movie getMovieData(@RequestParam String name) {

        String message = "Get me the best movie of {name}\n{format}";

        BeanOutputConverter<Movie> outputConverter = new BeanOutputConverter<>(Movie.class);

        PromptTemplate promptTemplate = new PromptTemplate(
            message,
            Map.of("name", name, "format", outputConverter.getFormat())
        );

        Prompt prompt = promptTemplate.create();

        String content = chatClient
                .prompt(prompt)
                .call()
                .content();

        Movie movie = outputConverter.convert(content);

        return movie;
    }
}
```

## Comparing List Output Converter vs Bean Output Converter

| Aspect | `ListOutputConverter` | `BeanOutputConverter<T>` |
|---|---|---|
| Output type | `List<String>` | A specific custom class (example: `Movie`) |
| Needs class info? | No | Yes — pass the target class (example: `Movie.class`) |
| Use case | Simple list of names/values | Structured object with multiple, differently-typed fields |
| Underlying interface | `StructuredOutputConverter` | `StructuredOutputConverter` |

## Quick Summary

| Concept | Meaning |
|---|---|
| `Movie` class (bean) | A plain Java class with fields matching the structure we want the AI's response mapped into |
| `BeanOutputConverter<T>` | A converter that maps an AI's response directly into a specific Java object/class, using generics to specify the target type |
| `new BeanOutputConverter<>(Movie.class)` | Creates the converter, explicitly telling it which class structure to expect |
| `outputConverter.getFormat()` | Returns a format description (matching the target class's structure) to include in the prompt |
| `outputConverter.convert(content)` | Parses the raw response and maps it into a fully populated instance of the target class |

## Practice Questions

**Q1: What is the key difference between how `ListOutputConverter` and `BeanOutputConverter` are constructed?**
A: `ListOutputConverter` only needs a conversion service (example: `DefaultConversionService`), while `BeanOutputConverter` also needs to know the specific target class (example: `Movie.class`), since it must map the response onto a custom object's fields.

**Q2: Why does `BeanOutputConverter` use generics (example: `BeanOutputConverter<Movie>`)?**
A: To specify exactly which class the AI's response should be mapped into, so the converter knows the structure (fields and types) it needs to produce.

**Q3: What interface do both `ListOutputConverter` and `BeanOutputConverter` implement?**
A: `StructuredOutputConverter`

**Q4: In the `Movie` class example, what four fields were defined?**
A: `movieName`, `leadCast`, `director`, and `year`.

**Q5: What does `outputConverter.convert(content)` do when using `BeanOutputConverter`?**
A: It takes the raw JSON-like text response from the LLM and parses/maps it directly into a fully populated instance of the target class (in this case, a `Movie` object).
