# Switching to Redis as a VectorStore

## Why Try Redis?

We've already implemented `VectorStore` using both `SimpleVectorStore` (in-memory, for learning) and `PgVectorStore` (PostgreSQL-based, production-ready). Now, let's explore another popular option: **Redis**.

> **Redis** is a well-known, **open-source, in-memory data structure store**. It's widely used because it is extremely **fast**. It's not always the best choice as a primary/traditional database for every use case, but it does provide solid support for vector storage, which is why it's a popular option in the Spring AI ecosystem.

## Two Ways to Use Redis for Vector Storage

Spring AI's documentation mentions two main options for using Redis as a `VectorStore`:

1. **Redis Cloud** — a hosted, cloud-based option (typically requires creating an account, and may involve payment beyond a limited free tier)
2. **Running Redis Locally via Docker** — the approach we will use in this course, similar to what we did with PgVector

## Step 1: Running Redis Using Docker

Instead of using Docker Compose this time, we'll run Redis directly using a **Docker command**.

**Syntax (general idea):**

```
docker run -d --name <container_name> -p <host_port>:<container_port> redis/redis-stack:latest
```

**Example (as used in this course):**

```
docker run -d --name redis-stack -p 6379:6379 redis/redis-stack:latest
```

**Explanation:**

- `redis/redis-stack:latest` → the Docker image for Redis Stack, which includes Redis along with additional modules needed for vector search support
- `-p 6379:6379` → maps Redis's default port (`6379`) from the container to your local machine
- If this is your first time using this image, Docker will need to **download it first**, which may take some time depending on the image size and your internet speed

### Verifying It's Running

Once the container starts, you can check **Docker Desktop** (or run `docker ps`) to confirm that your **Redis Stack** container is up and running, listening on port **6379**.

> **Tip:** Since you're no longer using PgVector in this section, you can safely **stop** your earlier PgVector container to save system resources, if you'd like.

## Step 2: Cleaning Up Previous PgVector-Specific Setup

Since we're switching from PgVector to Redis, a few PgVector-specific pieces are no longer needed:

### Remove from `application.properties`

- All PostgreSQL/PgVector-specific connection properties (database URL, username, password, schema initialization settings, etc.) — since we are no longer using Postgres

### Remove from `pom.xml`

- The **Docker Compose** dependency (`spring-boot-docker-compose`) — since we're now running Redis using a direct Docker command instead of Docker Compose
- The **PgVector** starter dependency — since we're no longer using PgVector

## Step 3: Adding Redis-Specific Dependencies

We now need to add two new dependencies for Redis support:

1. **Vector Store Redis starter** — Spring AI's Redis-specific vector store integration
2. **Spring Data Redis** — standard Spring support for working with Redis

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-vector-store-redis</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-redis</artifactId>
</dependency>
```

> **Note:** As with earlier dependencies in this course, exact artifact names may vary slightly depending on your Spring AI version — always cross-check with the latest Spring Initializr output or official documentation if something doesn't match.

## Step 4: Adding Redis-Specific Properties

Just like we configured database properties for PgVector, we now need to configure connection and indexing properties for Redis.

**Syntax:**

```
spring.data.redis.host=<host>
spring.data.redis.port=<port>
spring.ai.vectorstore.redis.initialize-schema=<true/false>
spring.ai.vectorstore.redis.index-name=<index_name>
spring.ai.vectorstore.redis.prefix=<prefix>
```

**Example (matching our Docker setup):**

```
spring.data.redis.host=localhost
spring.data.redis.port=6379
spring.ai.vectorstore.redis.initialize-schema=true
spring.ai.vectorstore.redis.index-name=product-index
spring.ai.vectorstore.redis.prefix=product
```

**Explanation:**

- `spring.data.redis.host` and `spring.data.redis.port` → tell Spring how to connect to our locally running Redis container
- `spring.ai.vectorstore.redis.initialize-schema=true` → tells Spring AI to automatically set up the necessary schema/index in Redis when the app starts (this is `false` by default, so it must be explicitly enabled)
- `spring.ai.vectorstore.redis.index-name` → the name of the search index Redis will use to store and search our vector data (example: `product-index`)
- `spring.ai.vectorstore.redis.prefix` → a prefix used to organize/identify the stored documents (example: `product`)

## Step 5: Understanding the Java Client Difference

When we used PgVector, we relied on **`JdbcTemplate`**, which comes with built-in support for connection pooling and general database interactions.

For Redis, things work a bit differently. Since Redis isn't a relational database, we instead use a dedicated **Java client for Redis**, called **Jedis**.

> Specifically, we will use **`JedisPooled`**, which provides efficient, pooled connections to Redis — this will be set up as a Spring **Bean** in our configuration class.

## Step 6: Updating `AppConfig` (Overview, Full Implementation Next)

Since we are no longer using PgVector, some things need to change in our `AppConfig` class:

- **Remove** the `JdbcTemplate` parameter and PgVector-specific builder configuration (like `.dimensions(...)`, since that was PgVector-specific)
- **Remove** unused imports related to PgVector
- We will now build our `VectorStore` bean using a **Redis-based implementation** instead, along with a `JedisPooled` bean

> The exact, complete code for this updated configuration (including the `JedisPooled` bean and the new `VectorStore` bean using Redis) will be implemented step by step in the next topic.

## Quick Summary

| Concept | Meaning |
|---|---|
| Redis | An open-source, in-memory data structure store, known for speed; supports vector storage via Redis Stack |
| Redis Stack | A Docker image that bundles Redis with additional modules needed for vector search |
| `spring-ai-starter-vector-store-redis` | Spring AI's dependency for Redis-based vector store support |
| `spring-boot-starter-data-redis` | Standard Spring Boot dependency for working with Redis |
| `spring.ai.vectorstore.redis.initialize-schema` | Property to enable automatic schema/index setup in Redis (`false` by default) |
| Jedis / `JedisPooled` | The Java client used to connect to Redis, providing pooled connections (used instead of `JdbcTemplate`) |

## Practice Questions

**Q1: What are the two main ways to use Redis as a `VectorStore`, according to Spring AI's documentation?**
A: Using Redis Cloud (a hosted service), or running Redis locally via Docker (the approach used in this course).

**Q2: Why was the Docker Compose dependency removed from `pom.xml` when switching to Redis?**
A: Because Redis is being run using a direct Docker command in this topic, rather than through a Docker Compose file, so the Docker Compose integration dependency is no longer needed.

**Q3: What property must be set to `true` to enable automatic schema/index initialization for Redis, and what is its default value?**
A: `spring.ai.vectorstore.redis.initialize-schema`, which defaults to `false`.

**Q4: What Java client is used to connect to Redis in this setup, and why is it needed instead of `JdbcTemplate`?**
A: Jedis (specifically `JedisPooled`) is used, because Redis is not a relational database, so `JdbcTemplate` (designed for relational/JDBC-based databases) doesn't apply here.

**Q5: What two Redis-specific properties are used to configure how documents are indexed and organized in Redis?**
A: `spring.ai.vectorstore.redis.index-name` (the search index name) and `spring.ai.vectorstore.redis.prefix` (a prefix used to organize/identify stored documents).
