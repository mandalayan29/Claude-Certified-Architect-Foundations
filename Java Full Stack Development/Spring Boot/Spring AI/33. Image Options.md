# Customizing Generated Images with Image Options

## Why Customize the Image?

In the previous topic, we generated a basic image using just a text description. But by default:

- The image quality was **standard**, not high-definition
- We had no control over the **size**, **style**, or other visual characteristics

Let's now learn how to customize these settings using **Image Options**.

## Step 1: Understanding `ImagePrompt`'s Second Constructor

Recall that `ImagePrompt` has multiple constructors. So far, we used the simplest one — just passing a `String`. But `ImagePrompt` also supports a constructor that accepts **both** the text query **and** a set of image options:

```java
ImagePrompt prompt = new ImagePrompt(query, imageOptions);
```

## Step 2: Building `OpenAiImageOptions`

To create these options, we use `OpenAiImageOptions`, along with its **Builder pattern**.

**Syntax:**

```java
ImageOptions imageOptions = OpenAiImageOptions.builder()
        .quality("<value>")
        .height(<value>)
        .width(<value>)
        .style("<value>")
        .build();
```

**Explanation:**

- `OpenAiImageOptions.builder()` → starts building our image configuration
- `.build()` → finalizes and creates the actual `ImageOptions` object (technically, an `OpenAiImageOptions` object, which **implements** the more general `ImageOptions` interface)
- In between, we can chain multiple configuration methods, as shown below

## Step 3: Available Configuration Options

Let's go through each customizable option, along with the **valid values** discovered through testing (and, helpfully, through the error messages OpenAI returns when an invalid value is used!).

### Quality

```java
.quality("hd")
```

**Valid values:** `"standard"` or `"hd"` (**lowercase** — using `"HD"` in uppercase resulted in an error: *"the value HD is invalid"*)

> **Tip:** This is a great example of how error messages themselves can help you discover the exact valid values/format expected by an API — when unsure, try a value, and let the error message guide you toward the correct one.

### Height and Width

```java
.height(1024)
.width(1024)
```

**Valid value (commonly supported):** `1024` (for both height and width)

> Smaller values (like `5` or `100`, tested during exploration) may not be properly supported — `1024` was confirmed to work correctly as a standard supported size.

### Number of Images (`n`)

```java
.n(1)
```

**Important limitation:** With **DALL·E 3** specifically, only **one image** can be generated per request — so setting `n` to anything other than `1` doesn't make practical sense with this model.

> If you're using a different model/version that supports generating multiple images at once, this option would become more useful.

### Style

```java
.style("natural")
```

**Valid values:** `"vivid"` or `"natural"` (confirmed via testing — other values, like `"real"`, resulted in an error listing these two as the only valid options)

- **`vivid`** → tends to produce more dramatic, stylized, hyper-real images
- **`natural`** → tends to produce more realistic, natural-looking images

## Full Example Code

```java
@GetMapping("/image/{query}")
public String genImage(@PathVariable String query) {

    ImageOptions imageOptions = OpenAiImageOptions.builder()
            .quality("hd")
            .height(1024)
            .width(1024)
            .style("natural")
            .build();

    ImagePrompt prompt = new ImagePrompt(query, imageOptions);

    ImageResponse response = openAiImageModel.call(prompt);

    return response.getResult().getOutput().toString();
}
```

## Step 4: Testing the Customized Image Generation

```

```

**Result:** Compared to the earlier, default-quality image, this version — generated with `quality("hd")` and `style("natural")` — produced a noticeably **more natural-looking, higher-quality image**.

> **Trade-off to note:** Generating higher-quality, customized images (especially at HD quality) may take a bit **longer** to process compared to default/standard settings — worth keeping in mind for user experience in a real application (example: showing a loading indicator while waiting).

## How to Discover Valid Values Yourself

A very practical lesson from this topic: **when you're unsure what values a particular option accepts, try setting an arbitrary or likely value, run the request, and read the error message carefully.**

```
Try a value (e.g., quality("HD"))
        |
        v
   Run the request
        |
        v
If invalid --> API returns an error message listing the VALID options
        |
        v
Use one of those valid values instead
```

This trial-and-error approach, combined with reading error messages carefully, is a practical and common way developers explore and learn the exact constraints of an API — especially when documentation might not list every detail explicitly.

## Quick Summary

| Option | Purpose | Valid/Tested Values |
|---|---|---|
| `.quality(...)` | Controls image quality | `"standard"`, `"hd"` (lowercase) |
| `.height(...)` / `.width(...)` | Controls image dimensions | `1024` (confirmed working) |
| `.n(...)` | Number of images to generate | Only `1` supported with DALL·E 3 |
| `.style(...)` | Controls visual style | `"vivid"` or `"natural"` |

| Concept | Meaning |
|---|---|
| `OpenAiImageOptions.builder()` | Used to configure custom image generation settings (quality, size, style, etc.) |
| `new ImagePrompt(query, imageOptions)` | Combines your text description with custom image options into a single prompt |
| Error-message-driven discovery | A practical technique: intentionally trigger an error to learn the exact valid values an API expects |

## Practice Questions

**Q1: What are the two valid values for the `quality` option, and what casing should they use?**
A: `"standard"` or `"hd"`, and they should be **lowercase** (using `"HD"` in uppercase resulted in an error).

**Q2: What image height and width value was confirmed to work correctly during testing?**
A: `1024` (for both height and width).

**Q3: Why doesn't setting the `n` (number of images) option to more than `1` make sense when using DALL·E 3?**
A: Because DALL·E 3 only supports generating **one image per request**, regardless of what value is set for `n`.

**Q4: What are the two valid values for the `style` option?**
A: `"vivid"` and `"natural"`.

**Q5: What practical technique was demonstrated for discovering the valid values an API option accepts?**
A: Intentionally trying a value (even if unsure it's correct), running the request, and carefully reading the resulting error message — which often explicitly lists the valid/accepted values.
