# Getting a List of Structured Objects (List of Beans)

## Goal

So far, we've retrieved:

- A `List<String>` of movie names (using `ListOutputConverter`)
- A **single** `Movie` object (using `BeanOutputConverter<Movie>`)

Now, let's combine both ideas: getting a **`List<Movie>`** — a list of fully structured movie objects, not just names.

## Step 2: Updating the Prompt Message

```java
String message = "Get me top five movies of {name}\n{format}";
```

**Explanation:**

- Just like our very first `List<String>` example, we're now asking for **multiple movies** (top five), not just one
- The `{format}` placeholder remains — but this time, it needs to describe a **list of movie objects**, not a single object

## Step 3: The Challenge — Specifying "A List of Movie"

Here's where things get a bit trickier than before.

- With `ListOutputConverter`, we didn't need to specify any particular class — it just handled `List<String>` generically
- With `BeanOutputConverter<Movie>`, we specified a single class: `Movie.class`

But now, we want something in between: **a `List` containing `Movie` objects specifically**. We can't simply write `Movie.class` (that's just one movie), and we can't use the plain `ListOutputConverter` either (since that's designed for a list of `String`, not a list of custom objects).

### The Solution: `ParameterizedTypeReference`

To solve this, `BeanOutputConverter` supports being constructed with a special helper: **`ParameterizedTypeReference`**.

```java
BeanOutputConverter<List<Movie>> outputConverter =
        new BeanOutputConverter<>(new ParameterizedTypeReference<List<Movie>>() {});
```

**Explanation:**

- `ParameterizedTypeReference<List<Movie>>` → this is a special Java technique used to represent **generic types with their full type information preserved** at runtime (something that's normally tricky in Java, due to a limitation called "type erasure")
- `new ParameterizedTypeReference<List<Movie>>() {}` → notice the empty curly braces `{}` at the end — this creates an **anonymous subclass** of `ParameterizedTypeReference`. Since `ParameterizedTypeReference` is an **abstract class** with no abstract methods to implement, we can create this anonymous class directly, without needing to write any additional method bodies
- By passing this into `BeanOutputConverter`, we're telling it: *"I want you to map the AI's response into a `List` of `Movie` objects, specifically"*

> **Why does this matter technically?** In Java, due to how generics work at runtime (a concept called **type erasure**), a plain `List<Movie>.class` reference isn't really possible — the JVM doesn't retain full generic type details by default. `ParameterizedTypeReference` is a common pattern (also used elsewhere in the Spring ecosystem) specifically designed to work around this limitation, preserving the full `List<Movie>` type information so libraries like Spring AI can correctly generate and parse structured output for generic types like this.

## Step 4: The Rest of the Flow (Same Pattern as Before)


**Explanation:**

- This follows the **exact same pattern** as before — get the format from the converter, build the prompt template, send it, then convert the raw response
- The only real difference is that `outputConverter.convert(content)` now returns a `List<Movie>` instead of a single `Movie`, because of how we constructed our `BeanOutputConverter` using `ParameterizedTypeReference`

## Full Example Code

```java
@GetMapping("/movies-list")
public List<Movie> getMovieList(@RequestParam String name) {

    String message = "Get me top five movies of {name}\n{format}";

    BeanOutputConverter<List<Movie>> outputConverter =
            new BeanOutputConverter<>(new ParameterizedTypeReference<List<Movie>>() {});

    PromptTemplate promptTemplate = new PromptTemplate(
        message,
        Map.of("name", name, "format", outputConverter.getFormat())
    );

    Prompt prompt = promptTemplate.create();

    String content = chatClient
            .prompt(prompt)
            .call()
            .content();

    List<Movie> movies = outputConverter.convert(content);

    return movies;
}
```

## Comparing All Three Approaches

| Converter Setup | Returns | Use Case |
|---|---|---|
| `ListOutputConverter` | `List<String>` | Simple list of plain values (example: just movie names) |
| `BeanOutputConverter<Movie>` | `Movie` | One fully structured object |
| `BeanOutputConverter<List<Movie>>` (via `ParameterizedTypeReference`) | `List<Movie>` | A list of fully structured objects |

## Why This Is So Powerful

This capability — asking an LLM to generate data and reliably mapping it directly into your **own custom Java objects**, including **lists of them** — is a major reason structured output converters are so valuable in real AI-powered applications.

> Instead of manually parsing text, splitting strings, or hoping the AI's response happens to be formatted correctly, you get **clean, ready-to-use Java objects**, which can be passed directly into the rest of your application's logic — database calls, UI rendering, further processing, and so on.

## Quick Summary

## Practice Questions

**Q1: Why can't you simply pass `List<Movie>.class` when constructing a `BeanOutputConverter` for a list of custom objects?**
A: Because of Java's type erasure, generic type details like `List<Movie>` aren't fully preserved at runtime with a plain `.class` reference — `ParameterizedTypeReference` is needed instead to properly capture this generic type information.

**Q2: What is `ParameterizedTypeReference`, and why is it used here?**
A: It's a special Java/Spring technique used to preserve full generic type information at runtime, letting `BeanOutputConverter` correctly understand that it should map responses into a `List` of a specific class (like `Movie`), instead of just a generic list or a single object.

**Q3: Why is it valid to write `new ParameterizedTypeReference<List<Movie>>() {}` with empty curly braces?**
A: Because `ParameterizedTypeReference` is an abstract class with no abstract methods that need to be implemented, so creating an anonymous subclass with an empty body is valid — its purpose here is purely to capture the generic type information.

**Q4: What does `outputConverter.convert(content)` return when the converter was built using `BeanOutputConverter<List<Movie>>`?**
A: A `List<Movie>` — a list of fully structured, populated `Movie` objects.

**Q5: Summarize the key difference between using `BeanOutputConverter<Movie>` versus `BeanOutputConverter<List<Movie>>`.**
A: `BeanOutputConverter<Movie>` maps the AI's response into a single `Movie` object, while `BeanOutputConverter<List<Movie>>` (built using `ParameterizedTypeReference`) maps the response into a list containing multiple `Movie` objects.
