# Implementing Real AI-Generated Descriptions

## Goal

Now let's replace our `"demo description"` placeholder with **actual AI-generated content**, using the `ChatClient` we set up earlier.

## Step 1: Injecting `ChatClient` into `ProductService`

```java
@Autowired
private ChatClient chatClient;
```

**Explanation:**

- `@Autowired` → since we already created a `ChatClient` **bean** in our `ChatClientConfig` class (from an earlier topic), Spring can automatically inject that same object here, in `ProductService`
- This confirms the benefit of setting up shared beans like this in a dedicated configuration class — we can reuse the same `ChatClient` object wherever it's needed, without recreating it

## Step 2: Building a Well-Crafted Prompt

Getting a good, professional-sounding description requires a **carefully written prompt** — not just a bare-bones request. Let's build this using `String.format(...)`.

```java
String descriptionPrompt = String.format("""
        Create a professional and engaging product description.
        Use the product name and category to craft a description
        that highlights the key features of the product.
        Keep it simple, engaging, and avoid technical jargon.
        Limit the description to 250 characters.

        Product Name: %s
        Product Category: %s
        """, name, category);
```

**Explanation:**

- `String.format(...)` → allows us to build a formatted string, substituting `%s` placeholders with actual values (`name` and `category`, in this case)
- The prompt text itself gives the AI clear **guidelines** on what kind of description to generate:
  - **Professional and engaging** tone
  - Based on the **product name and category**
  - **Simple, engaging language** — avoiding overly technical jargon
  - Highlighting **key features**
  - A **character limit** of 250 characters

### Why the 250-Character Limit?

> This is a great, practical, real-world detail: since this project reuses an **existing database** (from the original e-commerce project), and that database's `description` column has a **maximum length of 255 characters**, the prompt explicitly asks the AI to stay within **250 characters** — giving a small safety margin below the actual database limit.

> **General lesson:** When integrating AI-generated content into an existing system, it's important to respect any **existing constraints** (like database column limits) — either by adjusting your database schema if that's feasible, or by explicitly instructing the AI to generate content within those existing limits, as done here.

## Step 3: Sending the Prompt and Extracting the Response

```java
String description = chatClient
        .prompt(descriptionPrompt)
        .call()
        .chatResponse()
        .getResult()
        .getOutput()
        .getText();
```

**Explanation:**

- This follows the **same pattern** we learned much earlier in this course (in the `ChatResponse` and metadata topic) — using `.chatResponse()` instead of `.content()`, then digging into `.getResult().getOutput().getText()` to extract the final text
- Any of these approaches (`.content()` directly, or this more detailed `.chatResponse()...getText()` chain) would work here — this example simply demonstrates the more detailed version once again

> **A quick reminder about error handling:** This chain of calls could technically result in a `NullPointerException` if something goes wrong (example: an unexpected or empty response). For a real production application, proper null-checking should be added. For this course, the focus remains on the core AI feature itself, keeping the example code simple and easy to follow.

## Step 4: Returning the Real Description

```java
return description;
```

## Full Example Code

```java
@Service
public class ProductService {

    @Autowired
    private ChatClient chatClient;

    public String generateDescription(String name, String category) {

        String descriptionPrompt = String.format("""
                Create a professional and engaging product description.
                Use the product name and category to craft a description
                that highlights the key features of the product.
                Keep it simple, engaging, and avoid technical jargon.
                Limit the description to 250 characters.

                Product Name: %s
                Product Category: %s
                """, name, category);

        String description = chatClient
                .prompt(descriptionPrompt)
                .call()
                .chatResponse()
                .getResult()
                .getOutput()
                .getText();

        return description;
    }
}
```

## Step 5: A Small but Important Debugging Moment

While testing this, an easy mistake to make is **forgetting to actually change the return statement** — for example, accidentally still returning the old placeholder value (`"demo description"`) instead of the newly computed `description` variable, even after writing all the new logic above it.

> **Lesson:** Always double-check that your final `return` statement actually uses your **new** result — it's a surprisingly common and easy mistake to overlook, especially when replacing placeholder code step by step (as recommended in the previous topic).

After fixing this and restarting the application, the feature works correctly.

## Step 6: Testing the Real AI-Generated Description

1. On the frontend, enter a product name (example: "My Phone") and category (example: "Mobile")
2. Click **"Generate"**

**Result:** A genuinely AI-generated, professional-sounding description appears, for example:

> *"Introducing My Phone — your perfect mobile companion. Enjoy seamless connectivity, a stunning display, and long-lasting battery life. Capture every moment..."*

This is a huge improvement over manually typing a description — and it follows our specified tone, style, and character constraints.

> **Note:** If you're building this into your **own** project (rather than reusing this exact existing database), and you don't have the same 255-character database limit, feel free to adjust the prompt's character limit instruction to allow longer, more detailed descriptions if desired.

## Recap: The Complete Flow

```
User enters Name + Category on frontend
        |
        v
Frontend calls POST /product/generate-description
        |
        v
ProductController receives the request, delegates to ProductService
        |
        v
ProductService builds a detailed prompt (name, category, tone, length limit)
        |
        v
ChatClient sends the prompt to OpenAI
        |
        v
Response is extracted and returned back up the chain
        |
        v
Frontend displays the AI-generated description
```

## Quick Summary

| Concept | Meaning |
|---|---|
| `@Autowired private ChatClient chatClient` | Injects the shared `ChatClient` bean created earlier in the configuration class |
| `String.format(...)` | Used to build a detailed, well-structured prompt, substituting in the product's name and category |
| Character limit in the prompt | Explicitly instructing the AI to respect an existing constraint (here, the database's 255-character limit) |
| `.chatResponse().getResult().getOutput().getText()` | An alternative (more detailed) way to extract the AI's text response, equivalent to using `.content()` |

## Practice Questions

**Q1: Why was the `ChatClient` simply injected using `@Autowired` in `ProductService`, without needing to build it manually again?**
A: Because a `ChatClient` bean was already created in a dedicated configuration class earlier, so Spring can automatically provide (inject) that same shared object wherever it's needed.

**Q2: Why did the prompt specifically instruct the AI to limit the description to 250 characters?**
A: Because the existing database's description column has a maximum length of 255 characters, so the prompt stays safely within that existing constraint, respecting the limitations of the system being integrated into.

**Q3: What debugging mistake was made and caught during testing, and what lesson does it teach?**
A: The final `return` statement was accidentally left returning the old placeholder value instead of the newly generated description. The lesson: always double-check that your return statement actually reflects your latest logic, especially when replacing placeholder code incrementally.

**Q4: What two ways were mentioned for extracting the final text from a chat response, and are they equivalent?**
A: Using `.content()` directly, or using the more detailed `.chatResponse().getResult().getOutput().getText()` chain — both achieve the same result, just with different levels of detail exposed along the way.

**Q5: Why did clicking "Generate Image" fail at this point in the project?**
A: Because there is no backend endpoint/mapping yet to handle that request — similar to the initial state of the description generation feature before it was implemented.
