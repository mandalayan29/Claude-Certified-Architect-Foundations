# Moving to PgVector: A Production-Ready Vector Store

## Why Move Beyond SimpleVectorStore?

So far, we've been using **`SimpleVectorStore`**, which is great for learning how `VectorStore` works. But as mentioned earlier, `SimpleVectorStore` is meant **only for educational and experimental purposes**.

If you're building a **real project**, you need a proper, production-ready `VectorStore` implementation instead.

> Setting up a real vector database is usually a **one-time setup** for a project — once configured correctly, it just works going forward.

## Choosing an Implementation: PgVector

Spring AI's official documentation lists several `VectorStore` implementations to choose from (Azure, Cassandra, Chroma, Elasticsearch, MariaDB, Neo4j, Oracle, PgVector, Redis, SAP, and more).

In this course, we will use **PgVector**, mainly because:

- It's built on top of **PostgreSQL**, which is a very popular and widely-used database
- If you're already familiar with PostgreSQL, working with PgVector will feel familiar too

## What Is PgVector?

> **PgVector** is an **open-source extension for PostgreSQL** that adds vector storage and similarity search capabilities directly into a PostgreSQL database.

In simple terms:

```
Normal PostgreSQL Database
        +
 PgVector Extension
        =
 A database that can ALSO store embeddings (vectors) 
 and perform similarity searches
```

With PgVector, you get all the regular benefits of PostgreSQL, plus the ability to:

- Store document embeddings
- Perform similarity searches (just like we did with `SimpleVectorStore`, but now backed by a real, production-grade database)

## A Small Challenge: PgVector Isn't Built into PostgreSQL by Default

If you install PostgreSQL normally on your machine, it does **not** come with PgVector support out of the box. To enable it manually, you would need to:

- Download some extra extension files
- Place them into your PostgreSQL installation folder (the exact steps vary depending on your OS — Windows, Linux, or Mac)

This can be a bit tedious and error-prone, especially for beginners.

## The Easier Way: Using Docker

Instead of manually installing and configuring PgVector on your local machine, we can use **Docker**, which already has ready-made PgVector images available.

> When you run PgVector using Docker, it comes with **PostgreSQL already built in** — so you get a fully working Postgres + PgVector setup, without any manual extension installation.

### Two Ways to Run PgVector with Docker

1. **Docker Compose** *(the approach we will use in this course)*
2. **Directly running a Docker container** (a single command-based approach)

### Example: Running PgVector Directly via Docker (Reference Only)

The official Spring AI / PgVector documentation provides a ready command you can run directly with Docker to get PgVector up and running in a container. This is a simpler, one-off way to get started, though in this course we will instead use **Docker Compose**, since it's more convenient for managing configuration long-term.

> The Docker Compose file used in this course is provided in the accompanying GitHub repository for this course.

## What Happens When You Connect PgVector to Spring AI?

Once everything is set up correctly, running your Spring Boot application with PgVector configured will **automatically create a default table** in the database to store your vector data.

> If you prefer, you can also set up this table manually yourself — but by default, Spring AI handles this automatically for you.

## What We Need to Set Up

To use PgVector in our project, there are a few things we need to configure:

### 1. Add the PgVector Dependency

In addition to the dependencies we've already added (like the OpenAI starter), we now need to add a **PgVector-specific dependency** to our `pom.xml` file.

> **Reminder:** As covered earlier in this course, Spring AI has since moved to a **stable version**, and dependency names/artifacts may look slightly different depending on which version you're using. Always check the latest dependency snippet from Spring Initializr or the official documentation.

### 2. Configure Database Connection Properties

Just like connecting to any database in a Spring project, we need to provide standard database connection details:

- **URL** (the database connection address)
- **Username**
- **Password**

### 3. Configure Vector Store–Specific Properties

Beyond the basic database connection, PgVector also requires some **vector-specific configuration**, such as:

| Property | Purpose |
|---|---|
| **Index type** | Determines how the vector data is indexed for efficient searching |
| **Distance type** | Determines how "closeness"/similarity between vectors is measured (similar in spirit to the cosine similarity concept covered earlier) |
| **Dimensions** | The number of dimensions your embeddings have (matching your chosen embedding model) |
| **Max document batch size** | Controls how many documents can be processed/inserted together in a single batch |

> We will look at the exact property names and values when we implement this step by step in the next topic.
