# Adding AI Features to a Real Project: E-Commerce App Overview

## Why Work with an Existing Project?

Up to this point, everything we built was a fresh, learning-focused project. But in the real world, adding AI features usually means **integrating into an existing application** — not building everything from scratch.

> Whether you're starting a brand-new project or adding AI to something that already exists, the core Spring AI concepts we've learned so far still apply. The difference is mainly about **where** you plug these features in — a new package, or directly into existing files.

In this next part of the course, we'll take a **real, working e-commerce project** and gradually add AI features into it, **step by step** — rather than trying to do everything at once.

## Understanding the Project First

Before adding any AI features, it's important to understand what the project already does.

### What Is This Project?

This is a simple **e-commerce backend** — the kind of system used for buying and selling products online (groceries, electronics, and so on).

- **Backend:** A Spring Boot project (similar in structure to what we've built throughout this course)
- **Frontend:** A separate **React application**, which acts as the user interface (no Thymeleaf or server-rendered pages involved — the backend is a pure API)

## Exploring the Frontend (React Application)

### Setting Up the Frontend

To run the React frontend locally, the general steps are:

1. Navigate to the frontend project's directory (example: a folder like `ecom/frontend`)
2. Install the necessary packages
3. Start the development server

**Syntax:**

```
npm install
```

**Explanation:** Downloads and installs all the required dependencies/packages listed in the project (this may take a little time the first time you run it).

```
npm run <script_name>
```

**Explanation:** Starts the frontend application, typically launching it in your browser (the exact script name depends on how the project is configured — commonly something like `npm start` or `npm run dev`).

> **Note:** Once installed, this setup doesn't need to be repeated every time — it's mainly a one-time setup step for the frontend project.

### What the Frontend Looks Like

Once running, the frontend shows a simple e-commerce-style website, including:

- A **Home** page
- An **Add Product** page
- The ability to view products, grouped by category
- A basic **search** option
- A **cart** feature

> **Note:** Since the backend isn't running yet at this stage, the frontend initially shows as "disconnected" — this is expected, and gets resolved once we start the backend server.

## Exploring the Backend (Spring Boot Project)

### A Small Setup Note: Database Configuration

When first running the backend, a configuration error may appear related to a missing **database dialect** setting. This is fixed by adding the standard database connection properties to `application.properties` (similar to what we've done earlier in this course, when connecting to PostgreSQL for PgVector):

```
spring.datasource.driver-class-name=org.postgresql.Driver
```

> Along with this, standard properties like the database URL, username, and password also need to be set correctly, matching your local PostgreSQL setup.

### Testing the Full Application (Frontend + Backend Together)

Once the backend is running correctly, refreshing the frontend shows it now properly connects to the backend — initially showing **"no products available"**, since the database starts out empty.

### Adding a Sample Product

Using the **Add Product** page, a new product can be created by filling in details such as:

- **Name** (example: "Laptop for Dev")
- **Brand** (example: "Dell")
- **Description**
- **Price** (example: `$56`)
- **Category** (example: "Laptop")
- **Stock quantity**
- **Release date**
- **Product image** (uploaded as a file)

After submitting, this product now appears on the **Home** page, along with options to:

- **Update** the product
- **Delete** the product
- **Add to cart**

The product also becomes searchable (example: searching for "laptop for developers" successfully finds it), and it appears correctly when browsing by category (example: under "Laptops").

## Understanding the Backend Structure

### Database: PostgreSQL

This project uses **PostgreSQL** as its database. You need PostgreSQL installed and running for the backend to work correctly.

### The `Product` Table

The application manages a `product` table in the database, with columns including:

- `id`
- `brand`
- `category`
- `description`
- `image`, `image name`, `image type`
- `name`
- `price`
- `product available` (a flag indicating stock availability)
- `release date`
- `quantity`

> **Important:** You don't need to manually create this table yourself — the project uses **Spring Data JPA**, which automatically handles creating the necessary database table structure based on the defined Java model class.

### Key Backend Components

```
ProductController  --> Handles incoming API requests
        |
        v
ProductService      --> Contains the actual business logic
        |
        v
ProductRepository    --> Handles database queries (via Spring Data JPA)
        |
        v
Product (Model)       --> Represents the data structure (matches the database table)
```

#### `ProductController` — Available Endpoints

- **Get all products**
- **Get a product by ID**
- **Get a product's image by ID** (used specifically to fetch and display product images)
- **Create a new product**
- **Update a product by ID**
- **Delete a product by ID**
- **Search for products** (a simple e-commerce search feature)

#### `Product` (Model/Entity)

Represents each product's data, matching the database columns described above. Notably, the **image** field uses a special type (`@Lob`, for "Large Object") to properly store image data directly in the database.

#### `ProductRepository`

Mostly relies on **Spring Data JPA's built-in methods** for standard operations (fetching, saving, deleting), with one **custom query** specifically written to support the **search** feature.

#### `ProductService`

Contains the actual logic behind each controller endpoint — retrieving all products, adding a new product, deleting a product, searching products, and so on. The controller simply delegates to this service layer to perform these operations.

## Practice Questions

**Q1: Why does this part of the course start with an existing project, instead of building everything from scratch again?**
A: Because in real-world scenarios, adding AI features usually means integrating them into an existing application, rather than always starting a brand-new project — so this reflects a more realistic, practical scenario.

**Q2: What two main parts make up this e-commerce project?**
A: A Spring Boot backend (API only, no server-rendered pages) and a separate React frontend application.

**Q3: What database does this project use, and how is its table structure created?**
A: PostgreSQL, with the table structure automatically created by Spring Data JPA, based on the `Product` model class — no manual table creation is needed.

**Q4: What is the purpose of the `@Lob` type used in the `Product` model?**
A: It's used specifically for the image field, to allow storing large object data (like an image) directly in the database.

**Q5: What are the four main backend components involved in handling a product-related request, from start to finish?**
A: `ProductController` (handles the incoming request), `ProductService` (contains the business logic), `ProductRepository` (handles database access via Spring Data JPA), and `Product` (the model representing the data structure).
