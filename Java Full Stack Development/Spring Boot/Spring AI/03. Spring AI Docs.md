# Exploring the Spring AI Documentation

## Why Check the Documentation?

In this course, we will learn Spring AI step by step through videos. But it is always a good habit to also check the **official documentation**. Documentation is helpful when:

- You have a specific question
- You want to see more details about a feature
- You just want to explore what else is available

## Where to Find Spring AI Documentation

You can find the Spring AI documentation on the official **Spring website**, under the **Projects** section.

Steps to reach it:

1. Go to the Spring website
2. Click on **Projects**
3. Select **Spring AI**
4. Click on **Learn**
5. This takes you to the **Reference Documentation**

## Understanding the Version

While checking the documentation, you may notice different version types:

| Version Type | Meaning |
|---|---|
| **SNAPSHOT** | The current, still-in-development version. Things can change here. |
| **M6 (Milestone)** | An early preview version, used to try upcoming/extra features. |
| **GA (General Availability)** | The final, stable, released version. |

In this course, we will use the **SNAPSHOT** version, since the GA (final stable) version is expected to release soon after.

> **Note:** If Spring AI updates further after this course is created, the course content will also be updated to match.

## What the Documentation Says About Spring AI

The Spring AI documentation explains its main goal clearly:

> Spring AI aims to simplify the development of AI applications, without unnecessary complexity.

This matches what we already learned earlier — Spring AI removes the need to write separate, complex code for each AI model.

### Inspired by LangChain

The documentation also mentions **LangChain**.

- **LangChain** is a popular tool (mostly used with Python) to connect applications with LLMs
- **Spring AI is inspired by LangChain** — meaning it follows similar ideas
- However, Spring AI is **not an exact copy or replacement** of LangChain
- Spring AI lets you do many of the same things as LangChain, but directly in **Java**

### Abstraction: The Core Idea

The documentation repeats an important point:

> Spring AI provides abstraction, which is the foundation for developing AI applications.

This means:

- You don't need to write different, complex code for every single AI model
- Spring AI gives you one common way to work with any supported model

## What Topics Does the Documentation Cover?

The Spring AI documentation covers many topics, including:

- **RAG (Retrieval Augmented Generation)** – a concept we will learn later in this course
- **Different ways to interact with LLM models**, such as:
  - Chat (having a conversation with the model)
  - Chat Models (the underlying model used for chat)

### Chat Models for Different Providers

One interesting point from the documentation: **each provider has its own Chat Model**.

This might sound confusing at first, but it makes sense once you think about it:

- If you use **OpenAI** → you use the **OpenAI Chat Model**
- If you use **Anthropic** → you use the **Anthropic Chat Model**

So even though Spring AI gives you a common way of working, it still keeps a specific "Chat Model" implementation for each provider behind the scenes.

## Practice Questions

**Q1: Where can you find the Spring AI reference documentation?**
A: On the Spring website, under Projects → Spring AI → Learn → Reference Documentation.

**Q2: What is the difference between SNAPSHOT and GA versions?**
A: SNAPSHOT is the current, still-in-development version that can change. GA (General Availability) is the final, stable released version.

**Q3: What tool is Spring AI inspired by, and is it a direct replacement for it?**
A: Spring AI is inspired by LangChain, but it is not an exact replacement — it lets you do many similar things, directly in Java.

**Q4: What is the core idea repeated throughout the Spring AI documentation?**
A: That Spring AI provides abstraction, which is the foundation for building AI applications without unnecessary complexity.

**Q5: Why does each provider have its own Chat Model in Spring AI, even though Spring AI provides abstraction?**
A: Because behind the common abstraction, Spring AI still needs a specific implementation to correctly talk to each provider's API (example: OpenAI Chat Model, Anthropic Chat Model).
