# Customizing Text-to-Speech: Voice and Speed

## The Problem We're Solving

In the previous topic, our text-to-speech worked, but we had no control over two important things:

1. Which **voice** was used
2. How **fast** the speech played back

Let's fix both of these now.

## Step 1: Finding the Right Method

Just like with the transcription model, `OpenAiAudioSpeechModel` has **two versions** of `.call(...)`:

1. `.call(String text)` → the simple version we already used (no customization)
2. `.call(SpeechPrompt prompt)` → accepts a more detailed prompt object, which supports **options**

To customize voice and speed, we need to use the **second version**, with a `SpeechPrompt`.

## Step 2: Building a `SpeechPrompt`

```java
SpeechPrompt prompt = new SpeechPrompt(text, options);
```

**Explanation:**

- `SpeechPrompt` has multiple constructors — one takes just the text (similar to what we did before), and another takes **both** the text **and** an options object
- Since we want customization, we use the version that accepts both

## Step 3: Building the Options with `OpenAiAudioSpeechOptions`

Just like we've done with images and transcription, we use a **Builder pattern** to configure our speech options:

```java
OpenAiAudioSpeechOptions options = OpenAiAudioSpeechOptions.builder()
        .build();
```

This gives us a basic options object using default values, which we'll now customize.

## Step 4: Available Configuration Options

Looking at what `OpenAiAudioSpeechOptions.builder()` offers, we can configure:

| Option | Purpose |
|---|---|
| **Input** | An alternative way to set the text prompt (in addition to what's passed to `SpeechPrompt` itself) |
| **Model** | Which specific text-to-speech model to use |
| **Speed** | How fast or slow the generated speech plays |
| **Voice** | Which voice style to use |

### Available Models (For Reference)

OpenAI's text-to-speech supports different model versions, including:

- `tts-1`
- `tts-1-hd` (higher quality)

> In this example, the model setting was left at its **default** value (not explicitly changed) — the focus here is on adjusting **speed** and **voice** instead.

## Step 5: Setting the Speed

```java
.speed(1.5f)
```

**Explanation:**

- `.speed(...)` → accepts a **float** value
- **Valid range:** `0.25` (slowest) to `4.0` (fastest)
- `1.5f` → makes the speech **1.5 times faster** than the default/normal speed

> **Tip:** The `f` suffix on `1.5f` is required in Java to indicate this literal value is a `float`, not a `double`.

## Step 6: Setting the Voice

```java
.voice(Voice.NOVA)
```

**Explanation:**

- `.voice(...)` → unlike `speed` (which is a simple `float`), this expects a specific **enum** type called `Voice`, not a plain string
- This means you select from a **fixed, predefined list** of supported voices, rather than typing in an arbitrary name

### Available Voice Options

Based on what's available in the `Voice` enum, OpenAI provides several voice choices, including:

- **Alloy** (the default voice, if none is explicitly specified)
- **Echo**
- **Fable**
- **Onyx**
- **Nova**
- **Shimmer**

> There may be additional voice options available depending on your Spring AI version — it's worth checking the `Voice` enum directly in your IDE (or the official documentation) for the complete, up-to-date list.

## Step 7: Calling the Model and Extracting the Result

```java
SpeechResponse response = audioSpeechModel.call(prompt);
byte[] audioBytes = response.getResult().getOutput();
return audioBytes;
```

**Explanation:**

- `.call(prompt)` → this time, since we're using a `SpeechPrompt`, the return type is a `SpeechResponse` object (not a plain `byte[]` directly)
- `.getResult().getOutput()` → extracts the actual generated audio as a `byte[]`, following the same familiar pattern used throughout this course for extracting results from response objects

## Full Example Code

```java
@RestController
public class AudioGenController {

    private OpenAiAudioTranscriptionModel audioModel;
    private OpenAiAudioSpeechModel audioSpeechModel;

    public AudioGenController(
            OpenAiAudioTranscriptionModel audioModel,
            OpenAiAudioSpeechModel audioSpeechModel) {
        this.audioModel = audioModel;
        this.audioSpeechModel = audioSpeechModel;
    }

    @PostMapping("/api/tts")
    public byte[] textToSpeech(@RequestParam String text) {

        OpenAiAudioSpeechOptions options = OpenAiAudioSpeechOptions.builder()
                .speed(1.5f)
                .voice(Voice.NOVA)
                .build();

        SpeechPrompt prompt = new SpeechPrompt(text, options);

        SpeechResponse response = audioSpeechModel.call(prompt);

        return response.getResult().getOutput();
    }
}
```

## Step 8: Testing the Customized Speech

1. Restart the application
2. Send the same request as before (a product description text)
3. Export the raw response and save it as an `.mp3` file (as covered in the previous topic — remembering to include the `.mp3` extension)
4. Play the file

**Result:** Compared to the earlier, default version, this new audio is noticeably **faster** (matching our `1.5x` speed setting), and uses a **different voice** (Nova, instead of the default Alloy) — giving a clearly different listening experience.

> **Experimentation tip:** Since there are multiple voice options available (Alloy, Echo, Fable, Onyx, Nova, Shimmer), it's worth trying out a few different ones to hear which style best fits your particular use case or audience.

## Recap: What We Achieved

```
Text + Desired Options (speed, voice)
        |
        v
   SpeechPrompt (text + OpenAiAudioSpeechOptions)
        |
        v
audioSpeechModel.call(prompt)
        |
        v
   SpeechResponse
        |
        v

```

## Wrapping Up Audio Models

With this topic, we've now covered **both directions** of working with audio in Spring AI:

- **Speech-to-Text (Transcription)** → including customization like timestamps (SRT format) and language/translation
- **Text-to-Speech** → including customization like speed and voice selection

## Quick Summary

| Concept | Meaning |
|---|---|
| `SpeechPrompt` | Combines text and speech options into a single request object |
| `OpenAiAudioSpeechOptions.builder()` | Used to configure text-to-speech behavior (model, speed, voice) |
| `.speed(float)` | Controls playback speed, ranging from `0.25` (slowest) to `4.0` (fastest) |
| `.voice(Voice.X)` | Selects a specific voice from a predefined `Voice` enum (example: `NOVA`, `ALLOY`, `ECHO`) |
| `SpeechResponse` | The response type returned when using `SpeechPrompt`; requires `.getResult().getOutput()` to extract the final `byte[]` audio |

## Practice Questions

**Q1: Why couldn't we simply use `audioSpeechModel.call(text)` to customize the voice and speed?**
A: Because that simpler version only accepts plain text, with no way to specify additional options. To customize behavior, we need to use the `.call(SpeechPrompt)` version instead.

**Q2: What is the valid range for the `speed` option, and what do the minimum and maximum values represent?**
A: The valid range is `0.25` (slowest) to `4.0` (fastest).

**Q3: Why does the `voice` option require using the `Voice` enum instead of a plain string?**
A: Because voice selection is limited to a fixed, predefined set of supported options, and using an enum ensures only valid voice choices can be selected.

**Q4: Name at least three available voice options mentioned in this topic.**
A: Any three of: Alloy, Echo, Fable, Onyx, Nova, Shimmer.

**Q5: What is the default voice used if no voice is explicitly specified?**
A: Alloy.

**Q6: After calling `audioSpeechModel.call(prompt)` with a `SpeechPrompt`, how do you extract the final audio bytes from the response?**
A: By calling `.getResult().getOutput()` on the returned `SpeechResponse` object.
