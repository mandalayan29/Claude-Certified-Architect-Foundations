# Understanding Embeddings

## The Magic Behind AI

One of the most important concepts that powers how AI understands and relates text (and even images) is called **Embeddings**. This is a big part of how AI "understands" that different words or phrases are related to each other.

> **Note:** Embeddings are not the *only* thing that matters in AI, but they are an important building block, especially for search, recommendations, and related features.

## The Core Problem: Computers Only Understand Numbers

Computers work with numbers behind the scenes — everything eventually becomes `1`s and `0`s. But when we send **plain text** to an AI system, how does it understand meaning?

For example:

- "I love puppy"
- "I want to get a puppy"

Even though these sentences are phrased differently, the AI understands that both are related to the topic of a **dog**. How does it make that connection?

This is exactly where **embeddings** come in.

> Embeddings are typically stored in special databases called **vector databases** — we will cover that separately later. For now, let's focus on understanding what embeddings actually are.

## What Are Embeddings?

> **Embeddings are numbers** — specifically, **floating-point numbers** (numbers with decimal points).

Embeddings are used in many common, everyday AI-powered features, such as:

- **Search**
- **Clustering** (grouping similar items together)
- **Recommendations** (like the movie recommendation feature we built earlier)
- **Anomaly detection**
- **Diversity measurement**
- **Classification**
- **Spam filtering**

## How Are These Numbers Generated?

Here's an important detail: an embedding is **not just a single number** for a word, sentence, or image.

> Instead, embedding is represented as a **list of numbers**, and this list is called a **vector**.

So:

- The word "dog" → gets its own list of numbers (its embedding/vector)
- The word "cat" → gets its own list of numbers
- The word "laptop" → gets its own list of numbers

### Why Does This Help?

The key idea is: **related words get numbers that are close to each other**, while unrelated words get numbers that are far apart.

**Example (simplified, using a single number just for explanation):**

| Word | Example Value |
|---|---|
| Dog | 55 |
| Cat | 60 |
| Laptop / Software | 90+ |

In this simplified example:

- "Dog" and "Cat" have **close values** → because they are related concepts (both are pets/animals)
- "Laptop" has a **very different value** → because it is unrelated to "Dog" or "Cat"

> **Important:** This is a simplified example using just one number for explanation purposes. Real embeddings use **many numbers together (a vector)**, not just one.

## From One Dimension to Many Dimensions

A single number is very limited — it can't capture much detail about a word's meaning. So instead, embeddings use **multiple dimensions**.

```
1 number (1 dimension)    --> Very limited meaning captured
2 numbers (2 dimensions)  --> Can plot on an X-Y graph, a bit better
3 numbers (3 dimensions)  --> Even more detail, but still not enough
...
Many numbers (high dimensions) --> Captures much richer meaning and relationships
```

The more dimensions you use, the more accurately the AI can represent and compare meaning between different words or pieces of text.

### Real-World Example: OpenAI's Embedding Models

OpenAI provides different embedding models, and each one produces a different number of dimensions:

| Model | Number of Dimensions |
|---|---|
| `text-embedding-3-small` | 1536 |
| `text-embedding-3-large` | 3072 |

> There was also an older embedding model (commonly known as "Ada") used before these newer models — mentioned here just for awareness.

> **General rule:** The **larger** the number of dimensions, the **more accurate** the AI's understanding of relationships between words/text tends to be.

## Visualizing Embeddings (Simplified Example)

To make this easier to understand, imagine plotting embeddings on a simple graph (using just 2 dimensions, for visualization purposes only — real embeddings use far more dimensions).

Example words plotted: `Lion`, `Cat`, `Laptop`, `Dog`, `Puppy`, `Kitty`, `Software`, `Smartphone`, `Earth`, `Saturn`, `Java`, `Go`, `C++`, `Watermelon`, `Banana`

```
Animals group:      Dog, Puppy, Lion   --> plotted close together
                     Cat, Kitty         --> also nearby (related to animals)

Programming langs:   Java, C++, Go      --> plotted close together
                     (but far from the "Animals" group)

Fruits:              Watermelon, Banana --> plotted close together

Planets/Space:       Earth, Saturn      --> plotted close together
```

### Key Observation

Words that are **conceptually related** (example: `Dog`, `Puppy`, `Lion` — all animals) end up **close to each other** on the graph, while unrelated concepts (example: `Java`, a programming language, versus `Dog`, an animal) end up **far apart**.

This is exactly how embeddings help AI understand relationships between words — by placing related concepts numerically close together, and unrelated ones far apart.

> **Note:** In the real plotted example, most values fall within a normalized range (roughly between `-1` and `+1` on each axis). This is common with many embedding models.

## Can You Control the Number of Dimensions?

Yes — with some of OpenAI's newer embedding models, you can actually **limit the number of dimensions** you want to work with.

> **Important:** This dimension-limiting feature is currently only supported with OpenAI's `text-embedding-3-small` and `text-embedding-3-large` models — not all embedding models support this.

## Quick Summary

| Concept | Meaning |
|---|---|
| Embedding | A list of floating-point numbers (a vector) that represents the meaning of a word, sentence, or image |
| Vector | Another name for this list of numbers |
| Dimension | Each individual number in the vector; more dimensions generally mean richer, more accurate meaning |
| Vector Database | A special type of database used to store and search embeddings (covered separately) |
| `text-embedding-3-small` | An OpenAI embedding model producing 1536-dimension vectors |
| `text-embedding-3-large` | An OpenAI embedding model producing 3072-dimension vectors |

## Practice Questions

**Q1: What is an embedding, in simple terms?**
A: An embedding is a list of floating-point numbers (a vector) that represents the meaning of a piece of text (or image), which AI uses to understand and compare meaning.

**Q2: Why are embeddings represented as a list of numbers (a vector) instead of just a single number?**
A: A single number cannot capture enough detail about meaning. Using multiple numbers (dimensions) allows the AI to represent much richer, more accurate relationships between different pieces of text.

**Q3: If "Dog" and "Cat" have embedding values that are numerically close to each other, what does that indicate?**
A: It indicates that the AI considers these two concepts to be closely related (in this case, both being animals/pets).

**Q4: How many dimensions do OpenAI's `text-embedding-3-small` and `text-embedding-3-large` models produce?**
A: `text-embedding-3-small` produces 1536 dimensions, and `text-embedding-3-large` produces 3072 dimensions.

**Q5: Name at least three real-world use cases where embeddings are commonly used.**
A: Any three of: search, clustering, recommendations, anomaly detection, diversity measurement, classification, or spam filtering.

**Q6: Can the number of dimensions be limited/controlled with any OpenAI embedding model?**
A: Only with the newer models — `text-embedding-3-small` and `text-embedding-3-large` — not with all embedding models.
