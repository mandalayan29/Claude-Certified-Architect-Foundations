# Vector Similarity: Understanding Cosine Similarity

## Where Do We Store Embeddings?

Once we convert text into embeddings, a natural question comes up: **where do we store them?**

Just like normal applications store data in files or databases (traditional or non-traditional), embeddings are typically stored in a special type of database called a **Vector Database**. This will be covered in detail in upcoming topics.

Before we get there, let's first understand an important concept related to embeddings: **how AI measures whether two pieces of text are similar or not**. This concept is called **Vector Similarity**, and you can also find it explained in the official **Spring AI documentation**, under the Vector Databases section.

## The Core Question: How Do We Measure "Distance" Between Two Points?

If two embeddings are just points in space, how do we mathematically calculate **how close or far apart** they are?

### Option 1: Pythagoras Theorem (For Right-Angled Triangles)

If the two points form a **right-angled triangle**, we can use the classic Pythagoras theorem from school:

```
A² + B² = C²
```

To find the distance (`C`), you simply calculate:

```
C = √(A² + B²)
```

This works well, but only when the triangle formed between the two points is a **right angle**.

### Option 2: Law of Cosines (For Any Triangle)

But in real-world embeddings, the "triangle" between two points is usually **not** a perfect right angle. For this general case, we use the **Law of Cosines** — which is very similar to Pythagoras theorem, but with an added adjustment.

**Formula:**

```
C² = A² + B² - 2·A·B·cos(θ)
```

**Explanation:**

- `A` and `B` → the two vectors (or their magnitudes) being compared
- `θ` (theta) → the **angle** between the two vectors
- `cos(θ)` → the cosine of that angle

> Notice that this formula is basically the Pythagoras formula, with one extra term: `- 2·A·B·cos(θ)`. This extra term accounts for the actual angle between the two vectors, instead of assuming a perfect right angle.

## From Math to Programming: Cosine Similarity

In programming, we don't manually draw triangles — instead, we calculate something called **Cosine Similarity**, which is derived from this same law of cosines idea.

Cosine similarity tells us **how similar two vectors are**, based on the angle between them — regardless of their actual size/magnitude.

### Breaking Down the Calculation

To calculate cosine similarity between two vectors `A` and `B`, we generally need to calculate a few components:

```
1. A² (magnitude of A, squared)
        |
2. B² (magnitude of B, squared)
        |
3. Dot Product of A and B (a specific way of multiplying vectors together)
        |
4. Combine all of these using the cosine similarity formula
        |
        v
   Cosine Similarity value (tells us how close/similar A and B are)
```

> **Note:** The exact mathematical steps for each of these calculations involve concepts like the **dot product**, which is a specific way of combining two vectors mathematically. This tutorial does not go deep into re-deriving every mathematical step — the key idea to understand is: **cosine similarity uses these building blocks (magnitude and dot product) to tell us how close two vectors are, based on the angle between them.**

### From One Dimension to Many Dimensions

The example above works for a **single dimension** (or a simple 2D case). But remember — real embeddings often have **many dimensions** (sometimes over 1000, as we saw with OpenAI's models).

For multiple dimensions, the calculation needs a **summation** — meaning we repeat the same calculation across **every dimension**, and add up the results.

**Conceptually:**

```
For dimensions 1 to n:
    Add up the contribution from each dimension
        |
        v
Final combined value used in the cosine similarity formula
```

In programming terms, this simply means using a **loop** that goes through each dimension, calculating and adding values together, instead of doing it manually for just one or two dimensions.

## Do You Need to Write This Math Yourself?

Not always. Here are your options:

| Approach | Description |
|---|---|
| Write it manually | You can write your own reusable function/method to calculate cosine similarity, and reuse it wherever needed |
| Use built-in libraries | Some languages (example: **Python**, using **NumPy**) have built-in support for these calculations |
| Rely on existing tools/features | Sometimes, similarity calculations happen **automatically behind the scenes** (example: inside vector databases), without you needing to call the math function directly yourself |

> In **Java**, there isn't a built-in cosine similarity function by default — but you can write your own reusable method for it (which we will do in the next hands-on topic).

## Quick Summary

| Concept | Meaning |
|---|---|
| Vector Similarity | A way to measure how close or far apart two embeddings (vectors) are |
| Pythagoras Theorem | Used to find distance, but only works for right-angled triangles |
| Law of Cosines | A more general formula (`C² = A² + B² - 2·A·B·cos(θ)`) that works for any triangle/angle |
| Cosine Similarity | A calculation (based on the law of cosines idea) used to measure how similar two vectors are |
| Dot Product | A specific mathematical operation between two vectors, used as part of the cosine similarity calculation |
| Summation across dimensions | For multi-dimensional embeddings, the similarity calculation is repeated and summed across every dimension |

## Practice Questions

**Q1: Why can't we always use the simple Pythagoras theorem to measure the distance/similarity between two embeddings?**
A: Because Pythagoras theorem only works for right-angled triangles, and the relationship between two embedding vectors usually does not form a perfect right angle.

**Q2: What formula is used instead of Pythagoras theorem when the triangle is not right-angled?**
A: The Law of Cosines: `C² = A² + B² - 2·A·B·cos(θ)`

**Q3: What does "cosine similarity" measure?**
A: It measures how similar two vectors are, based on the angle between them — closer vectors (smaller angle) indicate higher similarity.

**Q4: Why is a "summation" needed when calculating similarity for embeddings with many dimensions?**
A: Because the similarity calculation needs to be performed across every single dimension of the vectors, and then all those results need to be added together to get the final similarity value.

**Q5: Does Java have a built-in cosine similarity function by default?**
A: No. Unlike some other languages/libraries (example: Python's NumPy), Java does not have this built in by default — you typically write your own reusable function for it.
